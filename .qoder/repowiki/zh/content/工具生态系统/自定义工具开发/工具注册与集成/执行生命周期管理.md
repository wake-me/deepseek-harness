## 简介
本文件系统性说明工具执行的生命周期管理机制，覆盖以下要点：
- execute 函数的契约要求：参数校验、错误处理、信号取消与超时。
- exec 对象提供的能力：token、signal、agent 注入、deferContext、concludeTurn 等。
- 工具的错误处理策略：异常捕获、结构化错误返回、输出校验与投影失败处理。
- 长时间运行工具的后台任务：jobs 系统的使用、状态流转、读取与取消。
- 实际生命周期示例：异步操作、资源清理、取消传播与最终结果提交。

## 项目结构
围绕“工具执行”和“后台任务”的核心代码分布在两个包中：
- tools（工具运行时）：提供工具注册、执行管线、事件水线（pre/around/post/result）、执行上下文与错误模型。
- jobs（后台作业）：提供作业注册、生命周期、读取、取消与完成监听。

## 详细组件分析

### 工具执行管线与 execute 契约
- 输入与模式
  - ToolExecutionInput 指定 callId、rootCallId、name、arguments、agent、parent、signal。
  - 工具呈现模式 mode：native/code/both，影响可见性与是否注入 run_code 传输。
- 执行阶段
  - prepare：参数校验、pre-execute 水线、守卫检查，决定 dispatch/final-result。
  - dispatch：around-dispatch 包装（可替换 signal），执行工具体。
  - finalize：post-execute 水线、definition.finalizeContent、投影与冻结、事件通知。
  - finish：仅做内容终态化与通知（用于跳过 post-execute 的快速路径）。
- 超时与取消
  - timeoutMs 声明协作式超时预算，由 around-dispatch 包装器生效；工具体必须观察并转发 exec.signal。
  - 取消分为“在工具体之前取消”和“在工具体之后取消”，分别对应不同错误码。
- 并发与安全
  - isConcurrencySafe 标记可并行分组；exclusive 形成屏障。
  - presentCall/presentResult 为纯函数，用于 UI 展示。

### exec 对象能力与注入点
- 只读视图 ToolExecution：包含 token、rootCallId、callId、name、arguments、agent、signal（不可变）。
- 可写视图 ToolDispatchExecution：允许 around-dispatch 替换 signal。
- 运行上下文 ToolRunContext：在工具体内可用，支持 deferContext（追加上下文到本轮）、concludeTurn（标记本轮结束）。

- parent token：用于 Code Mode 子调用的归属与等待。

### 错误处理策略
- 统一错误模型
  - ToolExecutionResult 区分成功与失败；失败携带 ToolFailure（message、info）。
  - 取消错误码：ABORTED（工具体已调用后取消）、ABORTED_BEFORE_DISPATCH（调用前取消）。
  - 未知工具：抛出 ToolNotFoundError（code=UNKNOWN_TOOL）。
  - 输出不合法：抛出 ToolOutputError（包含 violations）。
- 异常捕获与规范化
  - 任意抛出的值会被安全地转换为人类可读消息，避免被恶意对象破坏。
  - 投影失败（render/presentationMeta）会转为 ToolOutputError。
  - 快照与冻结确保结果可持久化且不可变。
- 水线与守卫
  - pre-execute 可 deny/ask；guard 提供单调拒绝（无法恢复为允许）。
  - post-execute 可 accept/replace/block，将纠正反馈转为失败结果。

### 后台任务与 jobs 系统
- 作业生命周期
  - start(spec)：预检访问、验证、所有者清理、准入，然后同步启动并返回 JobHooks。
  - read(id)：消费式读取增量文本；最终输出完成后幂等返回。
  - kill(id, caller, reason)：请求取消、标记 stopping/reported；生产者抛错不影响状态。
  - wait(id, timeoutMs, caller, signal)：等待结算或超时，不主动取消作业。
  - onJobDone/onJobsChanged：完成监听与可见集合变更监听。
- 状态机
  - running → stopping → completed/killed/failed（终端状态唯一）。
- 与工具执行的集成
  - 工具体可通过 JobRegistry.start 启动后台任务，并在 exec.signal 上响应取消。
  - 作业输出通过 read 流式获取，最终输出在 settle 后可幂等读取。

### 实际生命周期管理示例（步骤说明）
以下为典型场景的步骤流程（以伪步骤描述，非代码片段）：
- 启动后台任务
  - 在工具体中调用 JobRegistry.start，传入 kind、label、owner、run() 返回 JobHooks。
  - 保存 job id，以便后续 read/kill/wait。
- 异步推进与输出
  - 周期性调用 read(jobId) 获取增量文本，直到返回的 snapshot.status 为终端状态。
  - 若为最终输出型作业，settled 后 read 返回最终 output。
- 取消与清理
  - 当 exec.signal 触发时，调用 JobRegistry.kill(jobId, reason)。
  - 在 JobHooks.cancel 中尽快释放资源，并确保 done 决议。
- 结果回�
  - 工具体根据作业结果构建 ToolExecutionResult 的成功或失败分支。
  - 如需追加上下文，使用 exec.deferContext；如需结束本轮，调用 exec.concludeTurn。

## 性能考量
- 并发控制
  - isConcurrencySafe 允许将多个工具调用归并为并行组，减少串行开销。
  - run_code 子调用并发上限由 maxParallelSubCalls 配置，默认 10，可限制资源占用。
- 信号与取消
  - around-dispatch 可替换 signal 实现超时/重试，但需保证工具体快速响应取消，避免阻塞。
- 投影与快照
  - 输出投影与快照在 finalize 阶段进行，避免重复计算；冻结结果提升持久化效率。
- 作业读取
  - read 为消费式游标，避免重复读取；最终输出完成后幂等返回，便于重试。

## 故障排查指南
- 常见错误与定位
  - UNKNOWN_TOOL：工具未注册或被 restrict 隐藏；检查注册与作用域。
  - INVALID_TOOL_OUTPUT：工具返回的值或投影不符合 schema；检查 output.schema 与 render/presentationMeta。
  - ABORTED/ABORTED_BEFORE_DISPATCH：取消发生在不同阶段；检查 exec.signal 与超时配置。
  - 未知语言/无渲染器：code/both 模式缺少 codeRuntime 或未注册渲染器；检查部署配置。
- 调试建议
  - 订阅 tools/result 获取冻结的最终结果快照。
  - 使用 tools/code-dispatch-start/code-dispatch 追踪 run_code 子调用。
  - 对 JobRegistry 使用 onJobDone 与 list 观察作业状态变化。

## 结论
