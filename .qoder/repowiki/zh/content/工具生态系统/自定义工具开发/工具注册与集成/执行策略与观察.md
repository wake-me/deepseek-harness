## 简介
本文件聚焦工具执行的策略系统与观察机制，围绕以下关键点展开：
- tools/pre-execute 钩子：用于权限检查、访问控制与审批（ask/deny/allow）。
- ctx.tools.guard() 的单调拒绝机制：确保最终安全决策不可被后续逻辑“翻盘”。
- tools/execute 包装器：用于添加超时、重试、指标收集等横切能力。
- tools/post-execute 与 tools/result 钩子：用于结果处理、内容替换、阻断与最终观察。
- 提供完整的策略实现示例，展示如何构建安全的工具执行环境。

## 核心组件
- ToolExecutionInput / ToolExecution / ToolDispatchExecution：描述一次工具调用的输入、执行上下文与可替换信号视图。
- ToolDefinition：工具定义，包含 schema、输出契约、可选 finalizeContent、timeoutMs、并发安全标记、呈现函数等。
- ToolRuntime：注册表与执行管道，编排 pre-execute → guard → execute → post-execute → finalize → result。
- ToolGuard：单调拒绝函数，返回拒绝原因或 undefined。
- PreToolDecision / PostToolDecision：pre/post 阶段的决策类型。
- CodeDispatchLog / tool/code-dispatch-start / tool/code-dispatch：Code Mode 下子调度的日志与观察事件。

## 详细组件分析

### 策略系统：pre-execute、guard、execute、post-execute
- pre-execute（tools/pre-execute）
  - 作用：在工具体执行前进行权限检查、访问控制与审批（allow/deny/ask）。
  - 行为：支持异步监听；若 ask，则通过审批服务决议；未实现审批时降级为 deny。
  - 取消：监听需关注 exec.signal；审批取消会回退为拒绝。
- guard（ctx.tools.guard()）
  - 作用：在 pre-execute 之后、工具体之前执行的一组单调拒绝检查。
  - 单调性：一旦任意 guard 返回拒绝原因，后续无法将其翻转为允许；这是最终安全决策点。
  - 范围：全局与按 agent 作用域叠加，远祖先优先，近作用域后查。
- execute（tools/execute）
  - 作用：围绕工具体的“around”包装点，适合注入超时、重试、指标、限流等横切能力。
  - 信号融合：包装器可替换 exec.signal，但会与原始 caller 信号融合，不会丢失调用方取消。
  - 结果归一化：包装器返回的结果会被标准化为工具输出契约，保证一致性。
- post-execute（tools/post-execute）
  - 作用：对已分派的结果进行接受、替换内容/值、附加上下文或阻断（block）。
  - 阻断：将结果转换为错误，内容为反馈信息；可附带 additionalContexts。
  - 值替换：仅对成功结果有效，且必须遵循工具的 output.schema。
- finalize 与 finish
  - finalize：应用工具定义的 finalizeContent（最后一次内容变换），然后冻结结果。
  - finish：通知 tools/result 观察者，完成一次执行的生命周期。

### 观察机制：tools/result 与 Code Mode 子调度事件
- tools/result
  - 时机：在 finalize 之后、最终结果冻结后触发。
  - 语义：只读观察，监听器失败被隔离，不影响主流程。
  - 数据：携带冻结后的 ToolExecution 与 ToolExecutionResult。
- Code Mode 子调度
  - tool/code-dispatch-start：记录子调度开始（父/子 callId、工具名、参数）。
  - tool/code-dispatch：记录子调度结算（是否错误、模型可见内容）。
  - tools/code-dispatch-log：可在持久化副本上替换内容（如大文本预览），不影响程序实际值。

### 执行模式与安全边界
- code 模式折叠：在 code 模式下，模型直调只能调用保留的 run_code；其他工具必须在 SDK 程序中调用。
- 未知工具：不在可见集合中的工具以 UNKNOWN_TOOL 失败，保持历史路由兼容。
- 输出契约：工具返回值必须满足 output.schema；投影 render/presentationMeta 失败会转化为结构化错误。
- 并发安全：isConcurrencySafe 精确判定是否可与兄弟调用并行；默认独占。

### 超时、重试与指标（通过 tools/execute 包装）
- 超时
  - 工具声明 timeoutMs 作为协作式预算；由外部策略（如 dsh-tool-call-timeout-policy）通过 tools/execute 包装实现。
  - 工具体需正确响应 exec.signal 并在取消时达到静默。
- 重试
  - 在 tools/execute 中捕获特定错误并决定重试次数与退避策略。
- 指标
  - 在 execute 前后记录耗时、成功率、错误码等指标。

## 性能考量
- 预快照与冻结：参数与结果在进入策略前进行 JSON 快照与冻结，避免后续修改导致不一致。
- 信号融合：wrapper 与 caller 信号融合，避免嵌套 AbortSignal.any，减少监听开销。
- 并发安全：isConcurrencySafe 精确判定，默认独占，避免共享状态竞争。
- 最小化副作用：presentCall/presentResult 要求纯函数，便于回放与 UI 渲染。

## 故障排查指南
- 常见错误与定位
  - 未知工具：resolveExecution 找不到定义或 code 模式折叠拒绝，返回 UNKNOWN_TOOL。
  - 输出不合法：output.schema 校验失败，抛出 ToolOutputError。
  - 投影失败：render/presentationMeta 抛错，转化为结构化错误。
  - 审批缺失：ask 无审批服务或无 agent，降级为 deny。
  - 取消：ABORTED_BEFORE_DISPATCH（未进入工具体）或 ABORTED（已进入工具体）。
- 调试建议
  - 在 tools/pre-execute 中打印决策路径（allow/deny/ask）。
  - 在 tools/execute 中记录耗时与错误码。
  - 在 tools/post-execute 中拦截阻断原因与反馈内容。
  - 使用 tools/result 做最终审计与观测。

## 结论
该执行策略与观察机制通过分层水线与单调拒绝，构建了强一致、可观测、可扩展的工具执行环境：
- pre-execute 负责准入与审批，guard 提供不可逆的最终安全决策。
- execute 包装器统一承载超时、重试、指标等横切能力。
- post-execute 提供结果级策略（接受/替换/阻断），result 提供最终观察。
- Code Mode 子调度事件完善了对嵌套调度的可观测性。
结合这些机制，可以构建既灵活又安全的工具执行环境。

## 附录

### 策略实现示例（步骤清单）
- 注册工具
  - 定义 ToolDefinition，包含 name、description、parameters、output（schema + render + presentationMeta?）、可选 finalizeContent、timeoutMs、isConcurrencySafe、presentCall/presentResult。
- 配置 pre-execute
  - 订阅 tools/pre-execute，根据上下文与参数返回 allow/deny/ask；若 ask，确保监听 exec.signal。
- 注册 guard
  - 使用 ctx.tools.guard() 注册单调拒绝检查，返回拒绝原因或 undefined。
- 包装 execute
  - 订阅 tools/execute，实现超时、重试、指标收集；注意不要丢弃 caller 取消。
- 处理 post-execute
  - 订阅 tools/post-execute，选择 accept/block，必要时替换 content/value 或附加 additionalContexts。
- 观察结果
  - 订阅 tools/result，记录审计信息；对 Code Mode 子调度，订阅 tool/code-dispatch-start 与 tool/code-dispatch。
