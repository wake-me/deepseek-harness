## 简介
本文件全面介绍 DeepSeek Harness 的“会话遥测”能力：从采集点、数据格式、处理与传输流程，到 OpenTelemetry 集成、数据脱敏与安全机制、遥测协调器职责（聚合、去重、性能优化），以及配置自定义与排障方法。系统以“能力接缝”方式将采集侧与后端导出解耦：采集侧负责事件投影、逻辑记录构建、水落式脱敏与最小后端契约；OTel 后端仅负责将记录推入 OTLP 日志管线，批处理、重试、队列与丢失策略由 SDK 决定。

## 项目结构
- 采集契约与协调器：位于 session-telemetry 包，定义逻辑记录、后端接口、捕获模式（实时/按需）与手递游标等。
- OTel 后端实现：位于 session-telemetry-otel 包，基于 OTel JS SDK 的 LoggerProvider + BatchLogRecordProcessor + OTLP/HTTP 导出器，映射记录并管理生命周期关闭。
- CLI 启动开关：通过环境变量控制遥测行是否禁用，便于在启动层统一开关遥测。
- 示例配置：headless 测试用 cordis 配置演示如何挂载遥测插件与自定义脱敏规则。

## 核心组件
- 逻辑记录与会话共享状态
  - 逻辑记录包含通道（ledger/ops）、时间戳、预映射严重级别、最小身份属性与完整负载体。
  - 共享状态声明了部署选择的分享策略（full / feedback-only / disabled），用于向用户界面披露。
- 后端契约
  - emit：非阻塞入队，必须同步调用不阻塞主循环。
  - flush：可选提示，多数后端不实现，交由 SDK 批处理节奏。
  - shutdown：等待后端管线静默，失败被包容且不影响应用销毁。
- 协调器
  - 支持 live 与 on-demand 两种捕获模式。
  - 维护每会话的手递游标与 chunk 去重集合，确保只发送每个 turn/step 的首个 chunk。
  - 将 agent/error 总线事件中继为 ops 记录。
- OTel 后端
  - 构造 LoggerProvider、BatchLogRecordProcessor、OTLP/HTTP 导出器。
  - 将逻辑记录映射为 OTel 日志条目，按 channel 分属不同 instrumentation scope。
  - 提供 mode 选择与严格的参数校验、关闭超时保护。

## 详细组件分析

### 协调器（SessionTelemetryCoordinator）
- 职责
  - 订阅会话事件与关键生命周期事件，完成 adoption、project、redact、deliver。
  - 维护 per-session 的 chunk 去重集合与 handoff cursor，保证 at-most-once 语义。
  - 将 agent/error 总线事件转换为 ops 记录。
  - 支持 on-demand 回放：仅在反馈触发时读取规范日志前缀进行捕获。
- 关键流程
  - 捕获事件：assistant/chunk 仅首块通过；其他事件原样传递。
  - 严重级别映射：tool/result.isError 或 turn/end 错误原因映射为 error，其余 info。
  - 身份属性：session.id、event.type、event.seq，以及可选 cwd、parent_id、seed_length。
  - 关闭路径：在 fiber 销毁阶段为仍存活会话发出 shutdown 标记，再调用后端 shutdown。

### OTel 后端（OpenTelemetrySessionBackend）
- 职责
  - 根据 mode 选择行为：FULL 实时导出；FEEDBACK_ONLY 仅在反馈事件回放；DISABLED 本地保留。

  - 严格校验 exporter.url、processor.maxExportBatchSize、shutdownTimeoutMillis。
  - 关闭时带超时保护，避免 transport 挂起导致进程无法退出。
- 字段映射
  - time → timestamp/observedTimestamp
  - severity → severityNumber/severityText

  - 凭据不出现在会话事件中，因此不会随遥测泄露。
  - 脱敏由水落规则负责；默认无内置规则，需部署方挂载。

### 脱敏水落（session-telemetry/record）
- 扩展点：部署可挂载监听器对 outbound 记录进行转换或替换；未挂载则透传。
- 执行时机：live 模式在 append 时；on-demand 模式在回放规范日志时。
- 安全性：仅作用于导出副本，不修改规范日志；抛出异常的监听器会丢弃该条记录（fail-closed）。

### 指标采集点与数据格式
- 采集点
  - session/event：所有会话事件（助手消息、工具结果、turn 开始/结束等）。
  - agent/error：通过总线中继为 ops 记录。
  - 生命周期：session/disposed 与协调器销毁阶段输出 shutdown 标记。
- 数据格式
  - channel：ledger（镜像会话日志）或 ops（操作信号）。
  - time：Unix 毫秒时间戳。
  - severity：info/warn/error（error 来自 tool/result.isError、turn/end 错误原因、agent-error）。
  - attributes：最小身份属性（session.id、event.type、event.seq 及可选 header 信息）。
  - body：完整 event.data 深拷贝（或 op payload）。

### 遥测协调器的作用（聚合、去重、性能优化）
- 聚合：将多源事件（会话事件、agent/error、生命周期）统一为逻辑记录。
- 去重：固定 chunk 投影，仅首个 assistant/chunk 通过；手递游标避免重复。
- 性能：
  - 捕获路径零 I/O，仅内存操作与结构化克隆。
  - flush 为可选提示，避免阻塞主循环。
  - on-demand 模式减少常驻监听与内存占用。

### 数据脱敏与安全处理机制
- 默认无内置规则：未挂载监听器时，导出内容即原始捕获副本。
- 部署方责任：在 session-telemetry/record 水落挂载脱敏规则，过滤敏感字段。
- 凭据隔离：模型凭据不在会话事件中，不会随遥测泄露。
- 反馈模式下的快照：FEEDBACK_ONLY 不保留遥测副本，仅在反馈时回放规范日志并按当时规则脱敏。

### 遥测配置的自定义指南
- 模式选择
  - FULL：实时导出全部记录。
  - FEEDBACK_ONLY：仅在记录反馈时回放并导出前缀。
  - DISABLED：默认，不构造 SDK 管线，本地保留。
- 导出器配置
  - exporter.url：必需（除 DISABLED），必须为 http(s)。
  - 其他字段（headers、timeout、compression 等）透传给 SDK。
- 处理器配置
  - processor：透传给 BatchLogRecordProcessor；maxExportBatchSize 必须为正整数。
- 关闭超时
  - shutdownTimeoutMillis：正有限数，默认 3000ms。
- CLI 启动开关
  - 通过环境变量 DSH_TELEMETRY_DISABLED 注入补丁禁用遥测行。

## 性能考量
- 捕获路径零 I/O：仅内存操作与结构化克隆，避免阻塞主循环。
- 固定 chunk 投影：大幅降低流式输出的冗余数据量。
- 批处理与导出节奏：由 SDK 的 BatchLogRecordProcessor 控制，可通过 processor.scheduledDelayMillis 等调优。
- 关闭超时：防止 transport 挂起拖慢进程退出。

## 故障排除指南
- 常见问题
  - exporter.url 缺失或协议非法：加载时报错，检查 URL 是否为 http(s)。
  - maxExportBatchSize 非正整数：加载时报错，修正为正整数。
  - shutdown 超时：若超过 shutdownTimeoutMillis，provider.shutdown 将被放弃，可能丢失尾部记录。
  - 反馈模式下无导出：确认 mode 非 DISABLED，且存在 feedback/record 事件触发回放。
- 定位建议
  - 启用 console 日志观察警告信息。
  - 检查是否挂载了 session-telemetry/record 监听器（影响脱敏）。
  - 核对 CLI 环境变量 DSH_TELEMETRY_DISABLED 是否意外禁用了遥测。

## 结论
会话遥测以最小契约与明确边界实现了高内聚、低耦合的采集与导出体系。协调器负责捕获、投影、去重与脱敏调度；OTel 后端专注映射与生命周期管理。通过模式选择、严格校验与关闭超时，系统在可用性、性能与安全性之间取得平衡。部署方可通过水落规则与 SDK 参数定制满足多样化需求。
