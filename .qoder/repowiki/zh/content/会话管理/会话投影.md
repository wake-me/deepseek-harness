## 简介
本文件系统化阐述“会话投影”子系统的设计与实现。投影将原始会话事件转换为可读的业务对象，提供一致、可缓存、可持久化的当前值视图；配合查询能力，为上层提供高效的数据访问接口。文档覆盖以下要点：
- 投影的概念与作用：如何把事件流折叠成业务可用的整体值
- 投影注册表：驱动机制、变更通知、懒加载与动态卸载
- 投影缓存：策略、失效与自愈、冷读路径
- 统计信息：以投影方式收集与计算（如 Token 用量、上下文压力）
- 查询接口：基于会话查询的过滤、全文检索与关系追踪
- 扩展性：如何编写自定义投影并优化性能

## 项目结构
会话投影由三个关键部分构成：
- 投影注册表与驱动器：订阅会话事件，按单位纯函数推进状态，提供快照与检查点
- 投影持久化缓存：对每个会话的投影状态做落盘与冷读恢复
- 会话查询：在“首选实时”的逻辑会话语料上提供过滤、搜索、关系与窗口读取

## 核心组件
- 投影定义与类型表
  - 每个领域贡献一个 ProjectionDefinition，包含 key、schema、init、apply、view、stateVersion
  - SessionProjectionMap 是全局可扩展的类型表，承载所有键到值的映射
- 投影注册表
  - 订阅 session/event，对每个已注册单位进行 eager apply
  - 维护 per-session 的水位单元（UnitCell），支持懒构建与引用计数
  - 提供 snapshot、checkpoint、restoreFloor、viewCheckpoint、restore、onChanged
- 投影持久化缓存
  - 写后模式：按事件数或时间间隔节流，并在 turn/end 与会话释放时强制落盘
  - 冷读路径：从缓存行 + 持久化尾部回放 + 注册表恢复，失败软处理并自愈
- 会话查询
  - 统一抽象：列表、过滤、全文检索、关系追踪、窗口读取
  - 与投影解耦，但可复用会话事件源与逻辑会话视图

- 投影单位必须满足：

### 投影注册表：驱动、快照与恢复
- 驱动：监听 session/event，对所有注册单位执行 apply，仅在状态引用变化时触发变更通知
- 快照：snapshot 返回一致的 asOfSeq 与 values，values 经 schema 校验
- 检查点：checkpoint 产出 (ver, seq, val) 行，val 为结构化克隆，避免泄露内部引用
- 恢复：restore 使用 checkpoint + 尾部事件重放，检测日志收缩并拒绝不安全恢复
- 懒构建：首次访问某会话某键时，从 init 开始折叠历史

FoldInit --> Apply
Apply --> Changed{"引用是否变化?"}
Changed -- 是 --> Notify["通知 onChanged(带 schema 校验)"]

### 投影缓存：写后模式与冷读路径
- 写后模式：
  - 每事件递增 pending，达到阈值或超过时间间隔则写入
  - 两个强制落盘点：turn/end 与会话释放（detach）
  - 写入失败软处理，不影响主路径
- 冷读路径：
  - 先尝试 cachedSnapshot（零 I/O）
  - 否则 readFrom 获取尾部事件，调用 registry.restore 重放
  - 身份校验确保记录属于同一生命周期
  - 恢复后写回更近的检查点，下次冷读更快

## 性能考量
- 投影单位
  - 保持 apply 同步且轻量，未变化事件返回相同引用以避免下游开销
  - view 输出尽量小且稳定，减少序列化与传输成本
- 注册表
  - 懒构建单元，避免无谓的历史折�
  - 引用计数管理多插件挂载同一键的生命周期
- 缓存
  - 写后节流降低落盘频率；turn/end 与 detach 保证强一致点
  - 冷读路径优先使用缓存，失败再回退到持久化尾部回放
- 查询
  - 过滤与全文检索结合游标分页，控制单次响应大小
  - 窗口读取限制 before/after 范围，防止过大负载

## 故障排查指南
- 常见错误与定位
  - stateVersion 不匹配：恢复时丢弃旧行，需从头重放
  - 日志收缩：restore 检测到水印越界，要求从 seq 0 重新读取
  - 身份不一致：缓存记录与当前会话生命周期不符，视为无关记录
  - 写失败：缓存写入失败软处理，日志告警，下次自动自愈
- 建议步骤
  - 检查投影单位的 stateVersion 是否随状态结构变更而升级
  - 确认缓存配置（writeEveryEvents、writeIntervalMs）是否合理
  - 查看持久化 readFrom 返回的尾部事件是否与预期一致
  - 通过 onChanged 订阅定位具体键的变更时机与 seq

## 结论
会话投影系统将事件流转化为稳定、可缓存、可持久化的业务视图，并通过查询能力提供高效的数据访问。其设计强调：
- 纯函数驱动的投影单位，职责清晰、易于测试与扩展
- 注册表的懒构建与引用计数，兼顾性能与生命周期管理
- 缓存的写后模式与冷读路径，保障一致性与恢复能力
- 查询的解耦与组合，支持丰富的业务场景

## 附录：自定义投影开发指南
- 步骤
  - 在 SessionProjectionMap 中扩展键，定义值类型
  - 实现 ProjectionDefinition：
    - init：空日志的初始状态
    - apply：根据事件增量推进状态，未变化返回原引用
    - view：将内部状态转为对外可见的 wire 值
    - schema：对 view 输出进行校验
    - stateVersion：当状态结构或折叠语义变化时递增
  - 在插件中注册该单位，并可选择订阅 onChanged 获取变更
- 最佳实践
  - 保持 apply 同步与幂等，避免副作用
  - 最小化 view 输出体积，避免大对象频繁序列化
  - 合理使用 stateVersion，确保缓存行不被误用
  - 在高频事件中尽量返回不变引用，减少下游通知
  - 结合查询能力，将复杂计算下沉到投影，提升查询效率
