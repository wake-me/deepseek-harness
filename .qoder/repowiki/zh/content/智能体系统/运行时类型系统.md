## 简介
本文件系统性介绍 Agent 系统的运行时类型定义与类型安全机制，覆盖以下方面：
- 核心数据类型：Agent 配置、状态、事件与消息的结构化定义
- 类型验证与序列化：确保数据在持久化与跨边界传输时的一致性与完整性
- 类型扩展与自定义类型：如何在现有契约上安全扩展
- 类型安全的 API 使用示例：基于生成代码的调用方式

- 类型检查与调试工具：如何定位类型问题与生成产物

## 项目结构
Typert 将“源码分析、运行时存储、Loader 发现”解耦，并通过构建期生成器产出运行时校验 Schema（Zod）与客户端/宿主侧的类型声明。Session 子系统提供不可变的事件日志模型与严格的 JSON 边界；Agent 通过扩展 Session 事件映射注入领域事件；API Gateway 暴露 Typert 网关接口用于远程方法调用。

## 核心组件
- Typert 分析模型与发射器：从 TypeScript 源码抽取类型图，生成 Zod Schema 与类型声明，并输出宿主/客户端远端描述符

- Agent 事件扩展：通过模块合并向 Session 事件映射注入领域事件
- API 网关：统一的远程调用请求/错误码契约，配合 Typert 生成的描述符进行参数校验与结果解码

## 架构总览
Typert 的工作流：
1) 分析阶段：扫描工作区，构建 FaceModel 与 TypeGraph
2) 发射阶段：为每个包生成运行时 Schema（Zod）、类型声明与远端描述符
3) 运行阶段：会话写入前对事件数据进行 JSON 边界校验；网关调用依据描述符进行入参/出参校验

```mermaid

participant Gen as "Typert 生成器"
participant Host as "宿主服务"
participant Sess as "会话子系统"

Dev->>Gen : 编写类型与服务
Gen-->>Dev : 生成 Zod Schema / d.ts / 远端描述符
Host->>Sess : append(事件, 数据)
Sess->>Sess : isJsonValue(数据)
Sess-->>Host : 成功/拒绝
GW->>GW : invoke(InvokeRemoteRequest)
GW->>GW : 按描述符校验 args/result
GW-->>Dev : 返回结果或结构化错误
```

## 详细组件分析

### 会话事件与版本管理
- 会话事件采用强类型的判别联合，所有事件具备 seq/time，且仅“表面事件”携带 surfaceOp/sourceEventSeqs
- 通过 TurnEndReasonMap 等合并可扩展的枚举集合，插件可安全扩展终止原�
- 会话日志格式版本由单一常量控制，写端与读端统一读取；新增事件类型不强制升级，但结构性变更需升级版本
- ignorable 标记允许旧运行时跳过未知但非关键的事件，避免静默破坏重建逻辑

### Typert 类型图与生成产物
- 分析模型将 TypeScript 类型表达式抽象为 TypeNodeModel 树，记录声明、成员、泛型、交叉/联合等
- 发射器根据模型生成：
  - 运行时 Zod Schema 与导出
  - 类型声明文件（d.ts），将源类型投影为 ZodType
  - 宿主侧远端描述符（TYPERT_REMOTE），供网关调度与校验
- 支持命名空间、作用域、上下文绑定、取消信号等高级特性

### 类型安全的 API 使用（网关）
- 网关接收 InvokeRemoteRequest，按描述符校验 args，执行后返回业务结果或抛出结构化错误
- 错误码涵盖查找失败、参数无效、绑定无效、上下文不可用等，便于上层统一处理
- 可通过 Context.typertGateway 获取网关实例进行远程调用

```mermaid

GW->>Desc : 校验 args
Desc-->>GW : 通过/抛出 arguments-invalid
GW->>GW : 路由到实现/上下文
GW-->>Client : Promise<结果> 或抛出结构化错误
```

## 性能考量
- 会话事件写入前进行 JSON 边界校验，避免非法对象进入持久化层；校验为迭代遍历，避免栈溢出
- 生成器在构建期完成类型分析与 Schema 生成，运行时仅做轻量校验，降低热路径开销
- 表面事件与日志事件分离，减少不必要的元数据处理
- 会话日志版本单一整数，简化兼容性判断与迁移成本

## 故障排查指南
- 写入事件被拒绝：检查事件 data 是否为“无损 JSON”，必要时使用 snapshotJsonValue 获取可持久化副本
- 远端调用报 arguments-invalid：确认传入参数结构与描述符一致，注意 optional/wire 字段映射
- 旧运行时无法解析新日志：若新增事件未标记 ignorable，旧运行时可能拒绝重建；必要时升级会话格式版本
- 类型声明不匹配：检查生成器是否重新运行，确保 d.ts 与运行时 Schema 同步

## 结论
该运行时类型系统通过“静态类型 + 构建期生成 + 运行时校验”的三层保障，实现了：
- 强类型的事件与消息契约
- 可演进、可兼容的会话日志格式
- 跨边界的参数/结果校验
- 面向扩展的插件机制（事件合并、服务注册）
结合 Typert 生成器与 Session 子系统，Agent 系统在类型安全、可维护性与可观测性方面具备坚实基础。
