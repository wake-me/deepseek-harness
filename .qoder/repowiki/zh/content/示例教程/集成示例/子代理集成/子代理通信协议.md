## 简介
本文件系统化阐述子代理（Subagent）与父代理之间的通信机制、数据交换格式、消息类型与事件系统，覆盖一次性任务与可延续会话两种模式。文档还包含双向通信、实时数据传输、状态同步的完整示例路径说明；解释消息序列化、版本兼容性与错误传播；并给出网络通信的安全考量、加密传输与身份验证建议，以及性能优化与调试方法。

## 项目结构
子代理能力由“服务定义 + 多提供者”构成：
- 服务定义与运行时：`packages/subagent/subagent`

## 核心组件
- SubagentRuntime：服务入口，负责提供者注册、能力校验、一次性启动、可延续子代理管理、枚举与事件发布。
- SubagentContinuationManager：可延续子代理的激活、冷启动、FIFO 入队、中断、报告、收尾通知。
- Provider 抽象：统一 start/prepareContinuable 契约，支持进程内/进程外实现。
- 描述符（Descriptor）：持久化子代理元信息，用于冷启动与列表投影。
- 错误体系：统一的 SubagentError 类型与停止原因 stopReason。

## 架构总览
子代理通信分为两类：
- 一次性任务（One-shot）：通过 `start()` 启动，返回运行句柄，等待结果后结束。
- 可延续会话（Continuable）：通过 `startContinuable()` 创建持久会话，后续通过 `followup()` 投递消息，支持中断与报告。

```mermaid

participant Runtime as "SubagentRuntime"
participant Manager as "ContinuationManager"
participant Provider as "Provider"
participant Agent as "Agent/Session"
Caller->>Runtime : start(name, request)
Runtime->>Runtime : 能力校验/深度限制/Schema校验
Runtime->>Provider : start(ResolvedRequest)
Provider-->>Runtime : SubagentRun(id, localAgent?)
Runtime-->>Caller : SubagentRun
Note over Runtime,Provider : 一次性任务结束后 emit subagent/end
Caller->>Runtime : startContinuable(spec)
Runtime->>Manager : startContinuable(spec)
Manager->>Provider : prepareContinuable(request)
Provider-->>Manager : ContinuableCreateSpec
Manager->>Agent : 创建/冷启动并投递初始消息
Manager-->>Caller : {childId, messageId}
Caller->>Runtime : followup(parent, childId, content, options)
Runtime->>Manager : followup(...)
alt 已激活
Manager->>Agent : 入队下一条 FIFO 消息
else 未激活
Manager->>Agent : 冷启动并投递
end
```

### 可延续子代理的状态机与调度
- 激活态
  - running：有活跃入场或轮次，或唤醒入队工作。
  - waiting：空闲但仍有未释放的子激活。
  - settled：空闲且所有子已释放，管理器释放 AgentHandle。
- 路由策略
  - followup 根据激活态决定直接入队、唤醒或冷启动。
- 中断
  - interrupt(target, authority)：基于用户父会话或精确祖先 Agent 授权，取消当前轮次并保持队列。

### 双向通信、实时数据传输与状态同步示例
- 双向通信
  - 父→子：`followup(parent, childId, content, options)` 投递用户角色内容作为下一轮 FIFO。
  - 子→父：子代理通过 `reportFrom(child, content, options)` 向直接父发送报告，支持 quiet/wakeup 两种交付策略。
- 实时数据传输
  - 使用多次 followup 推送增量内容；子代理可在每轮中产出中间结果并通过 reportFrom 回传。
- 状态同步
  - 利用 `listChildren`/`listDescendants` 获取子代理存活与活动快照；结合 `subagent/start`/`subagent/end` 事件感知生命周期。
  - 可延续子代理的激活态变化由管理器内部维护，外部通过事件与列表接口观测。

### 网络通信安全、加密与身份验证
- 进程外后端
  - 默认不声明任何开始能力（outputSchema/depthLimit/toolFilter/persona 均不支持），由服务在 start 前拒绝需要这些能力的请求，避免跨进程误用。
  - 工作目录解析严格校验，防止越权访问。
- 安全建议（部署层面）
  - 使用 TLS 加密通道（如 gRPC/HTTPS）保护进程间或远程通信。
  - 对远端子代理进行身份认证（如 mTLS、JWT），并在服务端做最小权限校验。
  - 限制子代理可访问资源（沙箱、只读挂载、网络白名单）。
  - 对输入进行严格校验与长度限制，防范注入与资源耗尽。
- 注意
  - 本仓库的进程内提供者是可信同进程协作者；跨进程/网络的序列化与恶意输入校验应在真实进程、worker、持久化与模型边界完成。

### 性能优化技巧
- 复用可延续会话：对长任务使用 `startContinuable` + `followup`，减少创建/销毁开销。
- 批量与流式：将多条消息合并为一次 followup；子代理以流式方式逐步产出结果并通过 reportFrom 上报。
- 列表缓存：`listChildren`/`listDescendants` 使用三层阶梯（活体水印、投影缓存、持久化检查）加速查询。
- 控制并发：通过共享容量控制器延迟操作，但不耦合清理与结算。
- 避免不必要的能力：进程外后端不支持某些能力，提前拒绝可减少无效往返。

### 调试通信问题的方法
- 监听事件：订阅 `subagent/start`、`subagent/end`、`subagent/provider-added/removed`，定位生命周期断点。
- 检查能力：确认所选 provider 是否支持所需能力（outputSchema/depthLimit/toolFilter/persona）。
- 查看列表：使用 `listChildren`/`listDescendants` 获取子代理存活与活动情况。
- 中断与恢复：对卡住的子代理调用 `interrupt`，随后继续 followup 恢复队列。
- 进程外问题：检查工作目录、配置超时、进程退出码与日志；利用 `settleRunResult` 的错误归一化信息。

## 性能考虑
- 优先使用可延续会话以减少上下文重建成本。
- 合理设置中断与报告策略，避免频繁唤醒父代理。
- 使用列表服务的缓存层级降低 I/O 压力。
- 进程外后端避免使用其不支持的能力，减少无效协商与重试。
- 控制并发度，避免过多子代理同时抢占资源。

## 故障排查指南
- 无法启动子代理
  - 检查 provider 是否存在与能力是否满足。
  - 检查描述符快照是否成功，版本是否受支持。
- 消息未到达
  - 确认 followup 的父授权正确；检查激活态是否为 running/waiting。
  - 若目标不存在，走冷启动流程；关注异常与信号取消。
- 子代理卡住
  - 使用 interrupt 中断当前轮次；必要时 drain 指定祖先树下的后代。
- 进程外崩溃
  - 检查工作目录、配置超时、进程退出码；利用 settleRunResult 的错误归一化信息定位。
