## 简介
本文件面向需要在 Harness 中集成并管理“子代理”的开发者，覆盖 ACP、Claude Code、Codex 等不同类型的子代理。内容涵盖：
- 子代理能力与协议：启动请求、结果、可继续（continuable）会话、中断与报告
- 配置与通信：进程内/进程外提供者、工作目录、权限策略与环境变量
- 数据交换格式：结构化输出 schema、工具限制、角色化提示词
- 生命周期管理：启动、运行、中断、清理、冷恢复
- 错误处理与资源释放：失败语义、取消信号、优雅退出
- 性能监控与调试：事件、投影、日志与快照
- 安全与权限控制：沙箱、最小权限、环境隔离

## 项目结构
子代理系统由“服务定义 + 多提供者 + 模型侧工具 + 示例配置”构成：
- 服务定义与运行时：`packages/subagent/subagent`

## 核心组件
- SubagentRuntime：命名提供者注册、能力校验、一次性启动、可继续会话编排、枚举与生命周期事件
- SubagentProvider：具体子代理后端契约（start、可选 prepareContinuable、capabilities、inheritsParentContext）
- ContinuationManager：可继续子代理的激活、冷恢复、父子授权、报告投递、中断与回收
- 工具层：按 provider 委派调用、全局控制（send_message、list_agents）、子代理报告（report）

关键类型与职责（节选）
- SubagentStartRequest / ResolvedSubagentStartRequest：一次性启动请求（含 prompt、parent、signal、schema、depth、toolFilter、persona）
- SubagentResult / SubagentStopReason：终止结果与结束原�
- SubagentCapabilities：输出 schema、深度限制、工具过滤、角色化提示词支持
- ContinuableCreateRequest / ContinuableCreateSpec：可继续子代理的首次创建输入（如父历史种子）
- SubagentRun：一次性运行的句柄（id、localAgent、result、dispose）

## 架构总览
子代理通过“服务 + 提供者”解耦：上层只关心意图（启动、后续消息、中断、报告），提供者负责具体执行（进程内/外、不同产品）。

```mermaid

participant Caller as "调用方(工具/模型)"
participant Runtime as "SubagentRuntime"
participant Provider as "SubagentProvider"
participant Child as "子代理(进程内/外)"
participant Events as "生命周期事件"
Caller->>Runtime : start(name, request)
Runtime->>Runtime : 能力校验/描述符快照
Runtime->>Provider : start(resolved)
Provider-->>Runtime : SubagentRun(已发布)
Runtime-->>Caller : SubagentRun(id, localAgent?, result, dispose)
Runtime->>Events : emit("subagent/start")
Note over Child : 子代理执行任务...
Child-->>Runtime : 完成/错误/取消
Runtime->>Events : emit("subagent/end")
```

## 详细组件分析

### 一次性子代理（One-shot）
- 启动流程：构造请求 → 能力检查 → 持久化描述符 → 调用提供者 start → 返回运行句柄
- 结果语义：result 解析为 SubagentResult；stopReason 包含 completed/aborted/error/max-tokens/refusal 等
- 取消与清理：通过 AbortSignal 在启动前或运行中取消；dispose 确保资源释放

```mermaid
flowchart TD
Start(["开始"]) --> Validate["校验能力/最大深度/schema"]
Validate --> |通过| BuildDesc["构建持久化描述符"]
Validate --> |不通过| FailCap["抛出 UNSUPPORTED_CAPABILITY"]
BuildDesc --> CallProvider["调用 Provider.start()"]
CallProvider --> RunOK{"是否成功发布?"}
RunOK --> |是| ReturnRun["返回 SubagentRun"]
RunOK --> |否| Cleanup["清理未发布资源并拒绝"]
ReturnRun --> AwaitResult["await result()"]
AwaitResult --> StopReason{"结束原因"}
StopReason --> Completed["completed"]
StopReason --> Aborted["aborted"]
StopReason --> Error["error"]
StopReason --> MaxTokens["max-tokens"]
StopReason --> Refusal["refusal"]
```

### 可继续子代理（Continuable）
- 首次创建：保留稳定 childId，快照描述符，调用 provider.prepareContinuable（如有）生成种子，建立父子归属，提交初始提示
- 后续消息：followup 将消息入队到子代理收件箱；若无激活则冷恢复
- 中断：interrupt(targetSessionId, authority) 立即下发取消，不等待空闲；目标不存在视为 no-op
- 报告：reportFrom(child, content, options) 将选定内容投递给直接父代理（quiet/wakeup 两种调度）
- 回收：drainContinuableDescendants(parents) 按祖先范围关闭新接入并回收激活

### ACP 子代理提供者
- 进程外执行：每个子代理独立进程、会话、模型与工具，不共享 Cordis 上下文
- 能力声明：不提供 outputSchema/depthLimit/toolFilter/persona（由服务在 start 前拒绝）
- 工作目录：优先使用配置的 cwd，否则继承父会话 cwd（需存在且可进入）
- 权限策略：自动回答 session/request_permission（allow/reject）
- 环境变量：仅透传显式 env，父进程敏感信息会被清洗

## 依赖关系分析
- 服务与提供者松耦合：通过名称注册与能力声明进行匹配；缺失能力时“失败即告警”
- 可继续会话依赖 agents 服务；若无则相关 API 会明确报错
- 列举子代理依赖 sessionProjections 与 session store；缺少任一将抛错
- 生命周期事件以父作用域为键，便于隔离观察

## 性能考量
- 列举优化：对活性子代理使用水印快照；对冷子代理优先读取投影缓存，否则回退到持久化检查
- 队列模型：可继续子代理仅使用 Agent 收件箱作为唯一队列，保证顺序与可观测性
- 资源隔离：进程外提供者天然隔离，避免共享状态导致的竞争
- 取消与超时：统一通过 AbortSignal 与优雅退出宽限期控制，减少资源泄漏

## 故障排查指南
- 常见错误码
  - UNSUPPORTED_CAPABILITY：请求的能力未被所选提供者支持（如 outputSchema、toolFilter、persona、depthLimit）
  - NO_PROVIDER：未注册指定名称的提供者
  - CONTINUATION_UNAVAILABLE：可继续功能依赖 agents 服务但未挂载
  - CANCELLED：列举或读取被取消
- 诊断要点
  - 检查 providers 是否已注册（provider-added/provider-removed 事件）
  - 检查 sessionProjections 与 session store 是否可用（列举失败时）
  - 检查父会话 cwd 是否存在且可访问（ACP/Claude/Codex 要求）
  - 关注子代理停止原因（stopReason）定位模型/传输/配额问题
- 资源清理
  - 始终调用 run.dispose() 确保一次性运行释放资源
  - 使用 drainContinuableDescendants 在祖先销毁时回收可继续子代理

## 结论
子代理体系通过“服务 + 提供者”的清晰边界，实现了多种后端（ACP、Claude Code、Codex、进程内）的统一接入。一次性运行与可继续会话分别满足短时任务与长对话场景；能力校验、中断、报告、列举与事件机制提供了完整的生命周期管理与可观测性。结合示例装配，可以快速搭建从本地到产品级的子代理集成方案。
