## 详细组件分析

### headless-driver.ts：无头驱动与事件流
- 职责
  - 解析命令行参数（配置路径与任务）
  - 安装失败即崩溃钩子，加载环境变量，启动 Cordis 上下文
  - 运行单次 fixture 任务，并通过回调将每个 session_event 以 JSONL 形式输出
  - 最后输出 result 记录，确保可被上层测试消费
- 错误处理
  - 捕获异常并写入 stderr，设置退出码为 1
  - finally 中释放 fiber 资源，卸载钩子
- 事件流规范
  - 每行一个 JSON 对象，包含 type=“session_event” 与 event 字段
  - 最后一行为 result 记录，表示任务结束

### 快照断言：JSONL 规范化与比对
- 关键流程
  - 通过 runLoaderSmoke 启动 CLI 或库入口，收集 stdout 与持久化会话
  - 解析 JSONL，校验首条为 header、末条为 result，中间全为 session_event
  - 使用 normalizeSessionLog/scrubRequestHeaders/stabilizeRefreshLog/tokenizeSessionFixtureCwd 等工具消除不稳定因�
  - 支持 DSH_SNAPSHOT=replay 与 DSH_SNAPSHOT_FILE/OVERRIDE/CHILD_FILES 进行回放与覆盖
  - 将标准化后的流式 JSONL 与期望文件比对；必要时在刷新模式下重写期望文件
- 典型场景
  - 产品 headless profile 命令、模型失败、启动激活错误
  - 提供者重试、上下文溢出恢复、凭证缺失/无效提示
  - 高级工具链、目标工具、Ralph 循环、可继续子代理结算

### JSONL 格式规范（基于实现）
- 流式输出（stdout）
  - 每行一个 JSON 对象
  - 前若干行：type="session_event"，包含 sessionId 与 event
  - 最后一行：type="result"，表示任务完成
- 持久化会话（.sessions）
  - 文件扩展名可为 .jsonl 或 .jsonl.zstd（压缩）
  - 首行 header 包含 id、createdAt、cwd、parentSession 等元信息
  - 后续行为事件记录，按时间顺序追�
- 标准化要点
  - 去除请求头中的敏感字段
  - 统一 cwd、时间戳、会话 ID 等不稳定值
  - 支持回放时注入 override 与子会话文件集合

## 性能考虑
- 并行执行
  - 单测：fork 池隔离进程全局状态，避免竞争
  - E2E：通过 DSH_E2E_MAX_WORKERS 控制最大并发，默认 4，可降至 1 串行
- 超时与重试
  - E2E 测试超时 120s，hook 超时 30s，自动重试 2 次，缓解瞬时波动
- 覆盖率开销
  - 覆盖率仅在单测通道开启；E2E 不采集覆盖率，减少额外开销
- I/O 与持久化
  - 会话日志可能压缩（zstd），读取时需解码帧；快照刷新时批量写入期望文件

## 故障排查指南
- 常见错误定位
  - 启动失败：检查 headless-driver 的 stderr 输出与退出码
  - 凭证问题：缺失或非法密钥会在流中给出明确指引，注意不包含敏感字符
  - 回放失败：确认 DSH_SNAPSHOT 与 DSH_SNAPSHOT_FILE/OVERRIDE/CHILD_FILES 设置正确
- 调试技巧
  - 使用刷新模式（DSH_SNAPSHOT=refresh）生成新的期望快照
  - 查看持久化会话（.sessions）确认事件顺序与压缩完整性
  - 降低并发（DSH_E2E_MAX_WORKERS=1）复现竞态问题
- 覆盖率门控失败
  - 根据报告定位未覆盖分支，补充用例或合理调整排除项
