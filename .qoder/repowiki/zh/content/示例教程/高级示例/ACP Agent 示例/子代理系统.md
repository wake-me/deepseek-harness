## 简介
本文件系统性说明 ACP Agent 的子代理（Subagent）子系统，覆盖子代理的创建、管理、通信机制，生命周期、继承与作用域隔离，子代理间的数据传递、错误传播与结果聚合，以及嵌套子代理、并行执行、超时处理等高级特性。文档同时提供面向实践的配置示例与调用模式，帮助读者在真实部署中正确组合和使用子代理能力。

## 项目结构
子代理子系统由“服务定义 + 多种提供者实现 + 工具层”三部分构成：
- 服务定义：位于 packages/subagent/subagent，提供 ctx.subagents 运行时接口，负责注册提供者、能力校验、一次性启动、可延续子代理编排、枚举与事件。
- 提供者实现：包括进程内 spawn/fork、ACP 外部进程、Codex、Claude Code、Dsh SDK 等，各自实现 start/prepareContinuable 等契约。
- 工具层：tool-subagent/tool-subagent-control/tool-subagent-report 暴露模型侧工具（如 subagent/send_message/interrupt/list_agents/report）。

## 核心组件
- SubagentRuntime（ctx.subagents）：命名提供者注册表，能力校验，一次性启动 start，可延续子代理 startContinuable/followup/interrupt/reportFrom，枚举 listChildren/listDescendants，生命周期事件 emit。
- SubagentProvider：提供者契约，包含 name、capabilities、inheritsParentContext、start、可选 prepareContinuable。
- SubagentContinuationManager：可延续子代理的激活态管理、冷启动恢复、所有权图、消息路由、报告投递、排水关闭。
- 描述符（Descriptor）：持久化身份标识，区分 one-shot 与 continuable，携带 provider、label、agentOptions 快照等。
- 子代理构建（child-agent）：计算深度、应用工具过滤、注入 persona、合并策略覆盖。
- 生命周期事件：subagent/start、subagent/end、provider-added/removed。

## 架构总览
子代理系统采用“服务 + 多提供者 + 工具层”的分层架构：
- 上层通过工具层发起子代理请求（一次性或可延续），服务进行能力校验与描述符快照后委派给具体提供者。
- 一次性子代理返回运行句柄 SubagentRun，消费者等待 result 并 dispose 释放资源。
- 可延续子代理由 ContinuationManager 维护 Activation 驻留态，支持 followup 投递后续消息、interrupt 中断、reportFrom 上报父级。
- 枚举 API 直接读取会话存储与可选持久化缓存，不加载 Agent，提供稳定视图。

## 详细组件分析

### 一次性子代理（One-shot）
- 入口：SubagentRuntime.start(name, request)
- 流程：解析提供者 -> 能力校验（outputSchema/depthLimit/toolFilter/persona）-> 生成描述符 -> 调用 provider.start -> 观察生命周期事件 -> 返回 SubagentRun
- 结果：SubagentResult.output/structured/stopReason；非 completed 表示输出可能不完整
- 资源：必须调用 dispose 以取消剩余工作并达到静默

### 可延续子代理（Continuable）
- 入口：startContinuable(spec) -> 预留 childId -> 快照描述符 -> 调用 provider.prepareContinuable -> 材料化 Activation -> 提交初始消息 -> 返回 {childId, messageId}
- 后续消息：followup(parent, childId, content, options) 根据 Activation 状态路由到入队/唤醒/冷恢复
- 中断：interrupt(targetSessionId, authority) 授权后立即下发 cancel，不等待目标完成
- 报告：reportFrom(child, content, options) 将内容包装为用户消息投递到直父亲 Agent，支持 quiet/wakeup 两种调度策略
- 排水：drain()/drainDescendants(parents) 安全关闭并释放所有 Activation

### 枚举与发现：listChildren/listDescendants
- 直接读取会话存储与可选持久化缓存，不加载/恢复 Agent
- 使用投影单元折叠子代理身份（mode/label），按 createdAt 排序
- 对冷启动子代理提供降级路径（缓存命中则最终，否则 inspect 重算）
- 失败诊断：corrupt/unavailable 等，不影响健康子代理的可见性

## 性能与并发
- 可延续子代理的消息队列唯一性：Agent inbox 是唯一队列，保证顺序性与可观测性
- 列举优化：三层回退（活体水印缓存 -> 持久化投影缓存 -> 持久化 inspect），避免加载 Agent
- 并发控制：提供者可共享容量控制器但不得耦合兄弟结算/清理；管理器内部使用 ChildLock 串行化同一 childId 的关键区
- 资源释放：drain/drainDescendants 自上而下传播取消、自下而上释放 handle，确保有序回收
- 超时与中断：
  - 一次性子代理：通过 AbortSignal 控制启动前/后的取消；result 不会因子代理失败而 reject，而是 stopReason
  - 可延续子代理：interrupt 立即下发 cancel，不等待目标完成；followup/reportFrom 的 signal 仅控制准入阶段

## 故障排查
- 常见错误码与场景：
  - UNSUPPORTED_CAPABILITY：请求的能力（outputSchema/maxDepth/toolFilter/persona）不被提供者支持
  - NO_PROVIDER：未注册指定名称的提供者
  - CONTINUATION_UNAVAILABLE：缺少 agents 服务导致可延续功能不可用
  - UNAUTHORIZED：中断时父地址不匹配或祖先不在当前活体血缘中
  - ACTIVATION_CLOSING：报告投递时 Activation 正在关闭
  - PARENT_UNAVAILABLE：报告的目标直父亲不在线
  - CANCELLED：列举过程中被取消
- 定位建议：
  - 检查提供者 capabilities 与请求选项是否匹配
  - 确认 ctx.agents 与 sessionProjections 已挂载
  - 对于 ACP 提供者，检查工作目录是否绝对且可进入
  - 使用 listChildren/listDescendants 获取子代理状态与诊断信息

## 结论
子代理系统通过清晰的服务契约与多提供者架构，实现了灵活的一次性与可延续子代理编排。其设计强调：
- 能力前置校验与“失败即显式”原则
- 唯一消息队列与严格的父子授权
- 稳定的持久化身份与冷恢复能力
- 安全的排水与有序释放
- 高效的枚举与投影折�
这些特性共同支撑了嵌套子代理、并行执行、超时与中断等复杂场景的可靠实现。
