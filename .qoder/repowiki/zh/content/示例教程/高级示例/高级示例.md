## 简介
本高级示例文档面向有经验的开发者，聚焦 DeepSeek Harness 的高级能力与复杂应用场景，围绕两类典型示例展开：
- ACP Agent：面向自动化与程序化集成的 Agent Client Protocol（ACP）服务器，支持会话管理、权限控制、子代理、工作流、工具集成等。
- Headless Agent：无头编码代理，一次性任务驱动、持久化、子代理委派、工作流与 Ralph 迭代、JSONL 输出等。

文档将系统阐述设计思路、实现细节、技术要点，并给出端到端工作流程演示，覆盖配置管理、错误处理、性能优化等方面。

## 项目结构
示例位于 examples 目录下，包含多个可运行场景。其中 acp-agent 与 headless-agent 是本次重点：
- acp-agent：通过 JSON-RPC stdio 暴露 ACP 协议，适合父代理、子代理提供者与程序化客户端使用；默认组合包含沙箱、审批、子代理、工作流、Hooks、压缩、会话查询索引与重复调用提醒等。
- headless-agent：一次性任务驱动的无头编码代理，组合了模型适配器、本地 Bash/文件系统、子代理委派、工作流与 Ralph 迭代、todo_write、JSONL 持久化与检查点策略；还提供 E2B 沙箱覆盖的 POC。

## 核心组件
- 模型适配层：DeepSeek 适配器，开启思考模式与推理努力，支持多模型路由与上下文窗口配置。
- 会话与持久化：JSONL 持久化、压缩策略、检查点策略、会话投影注册表。
- 子代理与工作流：spawn/fork 两种子代理后端，可继续型后台子代理与一次性 fork；工作流引擎通过 worker-thread 执行脚本中的 agent() 调用。
- 工具栈：Bash、文件系统（含观察策略）、Ralph、Todo、Cordis 工具、可选 Code Mode。
- 权限与沙箱：按会话 cwd 隔离的沙箱策略，workspace-write/danger-full-access 模式切换；审批策略在危险模式下可设为 never，否则 ask。
- 钩子与扩展：Claude/Codex Hooks 桥接，按需加载；Code Mode 与 Cordis 工具可通过覆盖叠加启用。

## 详细组件分析

### ACP Agent 示例
- 目标与边界：以 JSON-RPC stdio 提供 ACP 协议通道，stdout 仅承载协议帧；stderr 用于诊断。每个 session/new 提供独立绝对 cwd，沙箱与文件系统写操作基于该 cwd 进行权限判定。
- 会话与权限：通过 DSH_PERMISSION_MODE 选择 workspace-write 或 danger-full-access；在 workspace-write 下，若模型重试请求更宽沙箱访问，会触发 session/request_permission，由客户端决定 allow_once/reject_once，且仅对当前重试生效。
- 子代理与工作流：同时暴露 spawn 与 fork 两种子代理工具，分别对应“可继续型后台”和“一次性 fork”；工作流引擎通过 worker-thread 将脚本中的 agent() 调用分发到 spawn 后端。
- 工具与钩子：文件系统走 dsh-fs-sandbox，配合 fs-observation-policy；Hooks 支持 Claude/Codex 两种协议，进程级读取一次，缺失即无操作。
- 高级模式：通过 advanced.cordis.yml 叠加 Code Mode 与 Cordis 工具，统一在一个 ACP 快照中验证所有边界。

```mermaid
flowchart TD
Start(["session/new"]) --> CWD["设置会话绝对 cwd"]
CWD --> Policy{"权限模式?"}
Policy --> |workspace-write| Sandbox["应用沙箱限制<br/>读写受 cwd 约束"]
Policy --> |danger-full-access| Full["放宽访问<br/>审批策略=never"]
Sandbox --> Tools["工具执行(文件系统/Bash)"]
Full --> Tools
Tools --> Result{"是否需要子代理/工作流?"}

Result --> |否| Persist["写入持久化/检查点"]
Sub --> Persist
Persist --> End(["返回最终文本/增量更新"])
```

### Headless Agent 示例
- 目标与边界：一次性任务驱动，接受非空任务后创建并持久化新会话，打印最终助手文本并退出；测试驱动通过 harness 注入固定 main 代理。
- 模型与工具：DeepSeek 适配器，本地 Bash 与文件系统；支持子代理委派、工作流、Ralph 迭代与 todo_write；JSONL 持久化与检查点策略。
- 高级模式：通过 advanced.cordis.yml 叠加 Code Mode 与 Cordis 工具，保持与基础组合一致的接口。
- E2B 覆盖：用 e2b.cordis.yml 替换本地文件系统与子进程提供者为共享 E2B 沙箱，证明最终删除；主机侧保留 Cordis、模型调用、会话状态等。

## 性能考量
- 令牌计量与压缩：token-meter 与 compaction-basic 在接近上下文窗口时自动摘要旧范围，降低延迟与成本。
- 工作线程与并发：workflow-worker-thread 通过 worker-thread 并行执行脚本中的 agent() 调用；todo 工具允许进行中任务并行。
- 沙箱与 I/O：文件系统与 Bash 受沙箱策略限制，避免不必要的跨会话干扰；E2B 覆盖集中 I/O 于单一沙箱，便于资源回收。
- 快照与持久化：JSONL 持久化支持压缩（zstd）与快照模式（关闭压缩）以平衡存储与回放速度。

## 故障排查指南
- 协议通道污染：ACP 示例要求 stdout 仅承载 JSON-RPC 帧；任何日志泄漏都会导致解析失败。测试通过断言每行均为有效 JSON 来保护。
- 注入与懒加载：session/new 路径需确保服务在 JSON-RPC 读取循环中可用；测试覆盖了从桥接到 AgentLoop 再到注册表/持久化的完整路径。
- 权限与沙箱：workspace-write 模式下若模型重试请求更宽访问，需通过 session/request_permission 明确 allow_once/reject_once；未决或不可用时应失败关闭。
- 清理与资源释放：Headless 测试在 afterEach 中确保 fiber 与临时目录被正确释放，防止残留进程或文件。

## 结论
ACP Agent 与 Headless Agent 示例展示了 DeepSeek Harness 在自动化与无头场景下的强大能力：通过声明式配置组合模型、工具、子代理与工作流，结合严格的权限与沙箱策略，实现安全、可观测、高性能的 AI 代理系统。高级模式叠加进一步验证了边界与兼容性，为生产级集成提供了可靠参考。

## 附录
- 快速运行
  - ACP：pnpm run demo:acp 或 demo:code-mode（需 DEEPSEEK_API_KEY）。
  - Headless：pnpm dsh --profile headless "任务描述"（需 DEEPSEEK_API_KEY，可选 BASE_URL）。
- 关键环境变量
  - DSH_PERMISSION_MODE：workspace-write 或 danger-full-access。
  - DSH_SNAPSHOT：影响持久化压缩与行为。
  - E2B_API_KEY：启用 E2B 覆盖时使用。
