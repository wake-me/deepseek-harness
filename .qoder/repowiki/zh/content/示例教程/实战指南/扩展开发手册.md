## 简介
本手册面向需要在 DeepSeek Harness（DSH）中构建可扩展、可维护的企业级扩展的开发者。内容覆盖插件架构、服务扩展、工具扩展、UI 扩展、动态包运行、事件处理、状态管理、扩展间通信，以及从需求到部署上线的完整工作流。通过官方文档与源码索引，帮助你快速定位实现位置并遵循最佳实践。

## 项目结构
DeepSeek Harness 采用“微内核 + 插件”的架构：核心子系统提供会话、系统提示、工具注册、Agent 循环等基础能力；所有业务特性以 Cordis 插件形式挂载到共享上下文 ctx 上。扩展可以围绕以下维度进行：
- 服务扩展：在 ctx 上暴露稳定 API（如 ctx.tools、ctx.sessions、ctx.agents）。
- 工具扩展：向模型暴露可调用工具，参与系统提示装配与执行策略。
- UI 扩展：订阅 session/event 流，渲染对话节点或面板。
- 动态包：允许 Agent 在运行时定义、运行、撤销插件（Host/Client 双半包）。
- 事件扩展：通过 typed events 进行跨插件通信与策略拦截。

## 核心组件
- 上下文与服务：插件通过 inject 声明依赖，将能力以稳定键名挂载到 ctx（如 tools、sessions、agents），其他插件按 key 发现，避免硬耦合。
- 事件系统：typed events 支持 emit、waterfall、parallel、serial 等分发模式，用于观察、包装、扇出、顺序决策。
- 工具管线：工具注册后自动进入系统提示装配与执行策略链（pre-execute → execute → post-execute → result），支持后台任务、超时、审计与呈现。
- 动态包：Host 负责定义、沙箱、生命周期；Client 负责浏览器侧评估与交互；两者通过请求-响应协议协作，并提供 inspect 查询。
- UI 扩展：基于 session/event 流渲染，并通过 agent.followup/steer/inject 驱动输入与上下文注入。

## 详细组件分析

### 插件与上下文（Cordis 基础）
- 插件是对象或服务，通过 inject 声明所需服务，apply(ctx) 完成注册。
- 所有注册都是可逆 effect，卸载时自动回滚。
- 事件分发模式决定监听器执行顺序与返回值语义。

```mermaid

Inject --> Apply["执行 apply(ctx)"]
Apply --> Register["注册服务/事件/工具/UI"]
Register --> Effect["effect 登记以便卸载"]
Effect --> End(["插件就绪"])
```

- 使用类型合并扩展 ctx 接口，使消费方获得类型安全。
- 服务之间通过 inject 解耦，避免启动顺序问题。

### 工具扩展
- 使用 defineTool 注册工具，schema 自动进入系统提示装配。
- 执行路径受策略层保护：tools/pre-execute（允许/拒绝/询问）、tools/execute（超时/重试/指标）、tools/post-execute（结果转换/附加上下文）、tools/result（只读观测）。
- 支持后台任务：run_in_background + ctx.jobs.start，返回句柄供 job_* 工具管理。
- 输出规范：output.schema 描述程序化返回值；output.render 生成模型可读内容；presentationMeta 用于 UI 卡片持久化。

### 事件扩展与状态管理
- 事件类型与分发模式由子系统页面生成，确保契约一致。
- 常用模式：
  - emit：无返回值，观察型。
  - waterfall：中间件式包装，next() 委派或短路。
  - parallel：并行监听，全部完成后决议。
  - serial：顺序监听，首个非空返回值即决议。
- 状态管理建议：
  - 使用会话日志作为单一事实源（append-only）。
  - 通过 ctx.effect 管理副作用，保证卸载有序。
  - 对长生命周期资源（PTY、子进程、网络）使用句柄与清理回调。

## 性能与可维护性
- 工具执行：
  - 使用 output.schema 描述程序化返回值，避免在 prose 中携带结构化数据。
  - 后台任务通过 ctx.jobs 管理，避免阻塞主循环。
  - 合理设置超时与取消信号（exec.signal）。
- 事件与状态：
  - 优先使用 append-only 会话日志，减少状态漂移。
  - 使用 waterfall 做策略层，保持单调性与可组合性。
- 动态包：
  - 严格区分 Host/Client 职责，避免跨域副作用。
  - 使用 inspect 工具进行只读诊断，不修改运行时。
- 代码组织：
  - 遵循添加包的清单（命名、导出、引用、README 模板）。
  - 将能力拆分为 Definition/Provider/Consumer 多包，便于独立演进。

## 故障排查指南
- 工具执行失败：
  - 检查 tools/pre-execute 是否拒绝；确认 exec.signal 是否被替换或提前中止。
  - 查看 tool/call 与 tool/result 事件，定位失败阶段。
- 动态包无法运行：
  - 使用 cordis_inspect_list 与 cordis_inspect_query 核对 Provider/方法签名。
  - 使用 cordis_inspect_self 查看当前 Plugin/Package 版本与运行态。
  - 若需浏览器侧能力，确认 request-run 流程已批准。
- UI 渲染异常：
  - 确认 session/event 订阅是否正确过滤 assistant/chunk。
  - 检查 presentCall/presentResult 的纯函数约束（不可访问会话状态或时钟）。
- 事件未触发：
  - 确认事件名称与分发模式匹配；检查 listener 注册是否在 effect 内。
  - 使用 prepend 控制优先级，必要时拆分监听器职责。

## 结论
DeepSeek Harness 通过 Cordis 插件框架与事件驱动的核心子系统，提供了高度可扩展的扩展体系。借助工具、服务、UI、动态包与事件机制，你可以构建企业级、可维护、可演进的解决方案。遵循本文的工作流与最佳实践，能够显著降低集成成本并提升稳定性。

## 附录：端到端工作流
- 需求分析：明确扩展目标（工具/服务/UI/动态包），识别所需核心能力（tools/sessions/systemPrompt/agents）。
- 设计与规划：选择合适的事件分发模式；设计工具 schema 与输出；划分 Host/Client 职责（动态包）。
- 实现：
  - 工具：defineTool + 策略层 + 后台任务（可选）。
  - 服务：inject 依赖 + ctx 键暴露。
  - UI：订阅 session/event + 渲染 + 输入驱动。
  - 动态包：定义 Package、Host/Client 半包、inspect 查询。
- 测试与验证：遵循仓库测试策略；使用快照与覆盖率要求；验证工具 schema 与呈现。
- 集成与发布：更新根配置（references、workspaces）；运行 doc-sync、constraints、typecheck、lint、build、hygiene；按需发布。
