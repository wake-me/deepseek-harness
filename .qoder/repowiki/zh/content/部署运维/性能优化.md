## 简介
本指南面向 DeepSeek Harness 项目的生产与开发环境，聚焦以下目标：
- Node.js 进程内存管理与调优（进程参数、垃圾回收策略、内存泄漏检测）
- 并发控制配置（Worker 线程池、连接池、资源限制）
- 数据库性能优化（查询优化、索引策略、缓存配置）
- 前端性能优化（代码分割、资源压缩、浏览器缓存）
- 性能监控与分析（APM 集成、指标采集、瓶颈识别）

本仓库在前端构建、CLI 启动流程、进程退出等方面提供了可落地的优化点；数据库与 APM 相关内容以通用实践为主，结合仓库现有能力给出建议。

## 项目结构

## 详细组件分析

### Node.js 进程参数与内存管理
- 运行时版本约束：根 package.json 指定 Node 引擎范围，确保使用较新的 V8 特性以获得更好的 GC 与性能
- 进程启动入口：通过根脚本中的 dsh 命令调用 CLI 二进制，便于在部署时统一传入 Node 参数（如 --max-old-space-size、--max-semi-space-size、--gc-interval 等）
- 优雅退出与超时：process-shutdown 提供统一的 shutdown/interrupt 接口，并内置超时强制退出，避免长时间 GC 或资源释放导致进程挂起
- 建议的调优要点
  - 根据工作负载设置堆上限与新生代大小，减少频繁 GC
  - 在高吞吐场景适当调整 GC 触发频率，平衡延迟与吞吐
  - 配合 heapdump 与 Chrome DevTools 进行堆快照对比，定位增长对象

### 垃圾回收策略与内存泄漏检测
- 策略选择：优先使用默认增量/并行 GC；对低延迟场景可尝试更激进的 GC 间隔
- 检测手段
  - 定期生成堆快照，比较差异定位持续增长的对象
  - 使用事件循环与 I/O 热点分析，排除长任务阻塞导致的“伪内存泄漏”
  - 在 CLI 中利用 process-shutdown 的超时机制，确保异常情况下不会长期占用资源
- 最佳实践
  - 避免全局大对象常驻；及时释放流、定时器、监听器
  - 对长会话数据采用分页与压缩存储，降低内存峰值

### 并发控制配置（Worker 线程池、连接池、资源限制）
- Worker 线程�
  - 代码运行与工具执行通常通过子进程或 Worker 线程隔离，需按 CPU 核数与 I/O 类型设定合理池大小
  - 避免过度并行导致上下文切换与内存压力上升
- 连接�

- 资源限制
  - 结合进程级限制（ulimit、cgroups）与进程内限制（队列长度、超时），形成双重保护
  - 使用 process-shutdown 的超时退出，保证资源释放可控

### 数据库性能优化（查询、索引、缓存）
- 查询优化
  - 仅选择必要字段，避免 SELECT *；合理使用 JOIN 与子查询
  - 将高频读路径下沉至缓存层，减少数据库压力
- 索引策略
  - 针对高频过滤、排序、关联列建立合适索引；避免过多写放大
  - 定期分析慢查询日志，持续优化索引
- 缓存配置
  - 使用本地内存缓存与分布式缓存分层；注意缓存一致性、过期策略与穿透防护
  - 对热点键做限流与降级，避免缓存击穿

### 前端性能优化（代码分割、资源压缩、浏览器缓存）

- 构建配置要点
  - 通过 manualChunks 精确控制分包边界
  - 通过 assetFileNames 与 chunkFileNames 规范输出布局

## 性能注意事项
- Node.js 进程
  - 根据机器内存与工作负载设置堆大小与 GC 参数
  - 使用堆快照与火焰图定位热点与泄漏
- 并发与资源
  - 合理设置 Worker 池与连接池上限，避免资源争用
  - 引入超时与熔断，防止级联失败
- 前端构建
  - 保持 vendor 稳定，减少不必要重打包
  - 懒加载重型模块，首屏只加载必需部分
- 数据库
  - 关注慢查询与索引命中率，定期优化
  - 使用缓存减轻数据库压力，注意一致性与失效策略
- 监控与分析
  - 接入 APM 收集关键指标（TTFT、吞吐、错误率、GC 时间）
  - 建立告警阈值与看板，持续跟踪性能趋势

## 故障排查指南
- 进程无法退出或退出缓慢
  - 检查 process-shutdown 的超时是否生效，确认是否有未释放的资源或阻塞的异步操作
  - 查看插件 dispose 逻辑是否正确
- 前端构建体积过大或首屏过慢
  - 检查 vendor 分包是否合理，确认重型库是否被正确拆分
  - 验证语言包是否按需懒加载，避免全部打入主包
- 启动阶段性能抖动
  - 观察 profile 组合与补丁层数量，减少不必要的 patch 与插件
  - 确认 HMR 仅在需要时启用，避免额外开销
