本模块由若干彼此独立的 npm 子包组成，按职责划分为四大类：
- extensions/cordis-*：实现动态插件的双半架构——`cordis-client-runner`（浏览器端）通过 `orchestrator.ts`、`runtime.ts`、`evaluator.ts`、`guard.ts`、`slot-catalog.ts`、`inspect-registry.ts`、`providers.ts`、`timer.ts` 协作，将宿主下发的代码编译为闭包并挂载到 Cordis 上下文；`cordis-host-runner`（宿主端）提供 `sandbox.ts`、`lifecycle.ts`、`registry.ts`、`guard.ts` 管理沙箱生命周期与插件注册；`tool-cordis` 暴露 `prompt.ts`、`present.ts`、`fiber-state.ts` 等工具能力；`ui-cordis` 基于 React 提供 `CordisPanel`、`CordisRunRow`、`CordisDefineRow` 等 UI 组件并通过 `slots.ts`、`card-model.ts` 与宿主通信。
- typert/*：类型协议栈，`protocol/src/types.ts` 定义跨进程契约，`loader` 负责加载，`generator` 通过 `analyzer.ts` + `model.ts` + `emitter.ts` + `renderer.ts` 对 TypeScript 工程进行静态分析并产出模型与代码，`tsdown-plugin.ts` 将其集成到构建流程，`registry` 提供 client/service 双端注册表。
- runtime-diagnostics/invariants：以 Cordis Service 形式提供可配置的运行时不变量注册中心，支持 allowlist/blocklist 过滤并按包名隔离检查。
- test-support/*：面向 e2e/snapshot 的支撑库，`acp-snapshot` 封装子进程启动、场景 harness、输出归一化与 suite 工厂；`client-runtime` 提供测试用会话/远程/工作区模拟；`llm-mock-server`、`llm-replay`、`agent-loop-testkit`、`loader-smoke` 分别覆盖 LLM 交互回放与加载冒烟测试。
- examples/*：`acp-demo`、`agent-spine-demo`、`jsonrpc-demo` 作为上述能力的端到端示例，各自带独立 bin 入口与 e2e 用例。
依赖方向单向收敛：examples/test-support 依赖 extensions/typert/runtime-diagnostics，extensions 之间仅通过 Cordis 上下文与服务契约解耦，不直接互相 import。
