本模块是 workspace 根下的 umbrella，不产出构建产物，仅通过 `package.json` 的 `workspace:*` 依赖把仓库内各 `@deepseek-ai/dsh-*` 包暴露给 Node 解析，使每个子目录成为独立的可执行示例。

- 子示例按用途划分：`acp-agent`（ACP 自动化服务器 + JSONL 持久化）、`headless-agent`（一次性 headless agent）、`jsonrpc-agent`（Python SDK 驱动的 JSON-RPC agent）、`mcp-memory`（第三方记忆服务 MCP overlay）、`web-cordis`/`web-schedule`（Web 插件演示）。
- 每个示例自带 `cordis.yml` 声明式插件树，通过 `!!js` 表达式读取 `DSH_SNAPSHOT`、`DSH_PERMISSION_MODE`、`DSH_CWD` 等环境变量切换运行时行为（如压缩开关、沙箱策略、模型选择），从而在同一份配置下同时支持真实运行与快照回放。
- 测试组织为两类：`tests/snapshots/<scenario>/` 存放 `input.json`、`session.jsonl`、`stdout.expected.jsonl`、可选 `system-prompt.expected.md`/`tool-schemas.expected.json` 的快照用例；`tests/*.e2e.ts` 使用 Vitest 启动真实子进程驱动 ACP/JSON-RPC，并配合 `launchAcpTestAgent`、`harness.ts` 等测试夹具完成进程生命周期管理。
- 快照机制由 `DSH_SNAPSHOT=record` 触发录制，再由 `*.snapshot.ts` 脚本对比回放输出；`replay.override.json` 用于在回放中注入固定时间/随机种子等确定性值。
- 依赖方向单向：示例 → 仓库内 `dsh-*` 包；测试 → 示例的 `cordis.yml` 与 bin；示例之间互不依赖，通过共享的 workspace 依赖获得一致性。
