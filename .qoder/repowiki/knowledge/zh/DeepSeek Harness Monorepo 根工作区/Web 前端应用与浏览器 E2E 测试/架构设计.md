模块由三层组成：
- 应用入口 `src/main.ts` 仅实例化 `AppWebEntry` 并挂载到 `#root`，所有加载器、模块表、插件装配与 AppRoot 门控均委托给 `@deepseek-ai/dsh-client-web` 包。
- 构建配置 `vite.config.ts` 通过自定义 Rollup `manualChunks` 将 math/highlight/markdown 等重型依赖拆出为独立的 `vendor` chunk（含 KaTeX、Shiki、micromark 系列），并将 `@shikijs/langs` 语法按需拆分到 `assets/langs/`，字体归入 `assets/fonts/`；同时用别名把 workspace 内的 `dsh-client-*` 包直接指向其 `src` 以走 Vite CSS 管线，并通过 `define` 注入 `process.versions.node='0.0.0'` 和 `node:module` 替换为 `src/node-module-stub.ts`，使 vendored Cordis Loader 能在浏览器中运行。
- 测试层位于 `tests/`，使用 Vitest + Playwright 启动真实 Chromium 驱动已构建的 dist，通过 `scaffold.ts` 在进程内组装 dsh-base 与 dsh-web-app 的 Cordis 组合，并以 `$DSH_SNAPSHOT` 环境变量切换 replay/record/refresh 三种模式；每个场景对应一个 `.e2e.ts` 文件及 `tests/snapshots/<scenario>/` 下的 `.expected.md/.jsonl` 黄金文件，配合 `.overlay.yml` 覆盖特定会话配置。`stress-tests/reasoning-chunks.stress.ts` 用于压力场景。依赖方向单向：测试 → 宿主服务（SessionStore、apiProxy）→ 真实 web 组合，禁止反向导入 Client 包以避免 Host/Client TypeScript 图冲突。
