模块按三层能力划分，每层均遵循「抽象服务 + 本地实现 + 工具/沙箱扩展」的分包模式：
- `packages/subprocess`：定义 `SubprocessRuntime` 抽象服务（`subprocess/src/index.ts`），暴露 `resolveExecutable`/`spawn`/`spawnTerminal` 三个抽象方法；`subprocess-local` 基于 Node `child_process` 与 `node-pty` 提供本地实现，维护 `live`/`terminals` 集合并在宿主退出时强制终止所有树。
- `packages/shell`：定义 `ShellExecutor` 抽象服务（`shell/src/index.ts`），统一 `run`/`start`/`resolve` 语义；`bash-local` 与 `pwsh-local` 是镜像实现的两个 Shell 执行器，通过 `ctx.subprocess` 派生 `bash -c` 或 `pwsh -Command` 命令，共享 `SHELL_SETTINGS_NAMESPACE` 配置并通过 `installSettingsSection` 热更新；`bash-sandbox`/`pwsh-sandbox` 在 exec 前用 `bwrap`/`landlock`/`seatbelt` 等机制对 argv 进行 confinement；`tool-bash`/`tool-pwsh`/`tool-bash-persistent`/`tool-pwsh` 将执行器包装为可被 Agent 调用的工具。
- `packages/terminal`：定义 `TerminalSessionService`（`terminal/src/index.ts`）作为 PTY 注册中心，维护后端 Map、owner-scoped session 表、名称预留与 pending spawn 队列，通过 `registerBackend` 注入具体后端；`terminal-bash` 实现 `BashTerminalBackend`，调用 `ctx.subprocess.spawnTerminal` 并注入 `TERM=dumb`、`PS1=CONTROLLED_PROMPT` 等环境，同时监听 `sandbox/mode` 事件阻止有活跃会话时的沙箱模式切换；`tool-terminal` 暴露交互式终端工具。
依赖方向严格自底向上：`subprocess` → `shell` → `terminal`，各层仅依赖其下层的抽象类型，不反向引用实现。
