本模块由四个相互依赖的 npm 包组成，形成「抽象服务 → 策略解析 → 本地后端选择器 → 平台具体实现」的分层：
- `sandbox/`：定义 `SandboxProvider` 抽象服务（继承自 `@deepseek-ai/cordis` 的 `Service`），注册到 `ctx.sandbox`；导出统一类型 `SandboxMode`、`SandboxPolicy`、`ConfinedArgv`、`RunnerFailureRule`、`SandboxEnforcement` 以及升级词汇表（`escalation.ts`）、工作区根路径工具（`roots.ts`）。
- `sandbox-policy/`：实现 `SandboxPolicyService`（`ctx.sandboxPolicy`），负责部署默认模式、会话级 `sandbox/mode` 事件覆盖、workspace-root 解析，并把最终策略注入系统提示上下文，供所有执行端消费。
- `sandbox-local/`：实现 `LocalSandboxProvider`，按平台选择 runner 链（Linux: bwrap→landlock；macOS: seatbelt；Windows: windows-acl），通过功能探测仲裁候选者，缓存选定 runner 及 denial signatures / runner failure rules；对 Windows 路径还维护每 workspace 的 standing ACE 缓存与每 session 的临时 temp SID 能力，并在 provider dispose 时回收。
- `sandbox-windows-acl/`：纯 Windows 实现，封装 `AclSandbox`（受限令牌 + WRITE_RESTRICTED + 双 SID 写权限列表）、`AclWriteGrant`（DACL 授予/撤销）、Win32 FFI（`ffi.ts`）、受限 token 创建（`token.ts`）、子进程 spawn（`spawn.ts`）、路径边界校验（`path-boundary.ts`）和基于工作区路径派生的 SID（`workspace-sid.ts`），并通过 `verify/abi-probe.cpp` 在构建期验证 ABI 兼容性。
依赖方向严格单向：`sandbox-local` 依赖 `sandbox` + `sandbox-policy` + `sandbox-windows-acl`；`sandbox-windows-acl` 仅依赖底层 Win32 API；`sandbox-policy` 仅依赖 `sandbox`；`sandbox` 不反向依赖任何实现包。每个包均自带 `src/`、`tests/`、`package.json`、`tsconfig.json`，并遵循 cordis 服务注册约定（`declare module '@deepseek-ai/cordis'` 扩展 Context）。
