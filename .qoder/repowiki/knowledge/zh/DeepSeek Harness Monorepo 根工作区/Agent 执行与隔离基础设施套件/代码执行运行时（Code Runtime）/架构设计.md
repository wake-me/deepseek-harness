模块由两个独立 npm 包组成，形成「抽象服务定义 + 具体后端」的分层结构：
- `code-runtime/`（`@deepseek-ai/dsh-code-runtime`）仅暴露纯类型与抽象基类 `CodeRuntime`（继承自 `@deepseek-ai/cordis` 的 `Service`），并通过 Cordis 上下文扩展声明 `ctx.codeRuntime`；集中维护跨语言可移植的保留字集合（`PORTABLE_RESERVED_WORDS`）、保留全局名（`RESERVED_BINDING_GLOBALS`）和错误成员白名单（`RESERVED_ERROR_MEMBERS`、`DUNDER_MEMBER`），作为所有后端的单一可信来源。
- `code-runtime-worker-thread/`（`@deepseek-ai/dsh-code-runtime-worker-thread`）实现 `WorkerThreadCodeRuntime`，通过 `node:worker_threads` 为每次 `run()` 启动一个全新 Worker，使用 `stripTypeScriptTypes` 将模型源码包裹成 async function body 并剥离类型，再通过 message port 与宿主通信；协议消息经 `parseWorkerMessage` 严格校验后再处理，调用方传入的 binding 函数返回值用 `snapshotJsonValue` 做 lossless JSON 快照。
- 资源隔离通过 `resourceLimits.maxOldGenerationSizeMb`、空 `env`、`execArgv: []` 以及 `stdout/stderr` 管道捕获实现；超时采用双预算——基于 `performance.eventLoopUtilization()` 的 busy-time 预算（`computeMs`）与 wall-clock 上限（`maxWallMs`），并由 `OutputLedger` 统一限制 logs/value/error 的序列化字节数。
- 依赖方向单向：worker-thread → code-runtime（类型与保留集），不反向引用；构建产物通过 `tsdown.config.ts` 单独打包 `lib/worker.cjs` 供 pkg VFS Worker hook 加载。
