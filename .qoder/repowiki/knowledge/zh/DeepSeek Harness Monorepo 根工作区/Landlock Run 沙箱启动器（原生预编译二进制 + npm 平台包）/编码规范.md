- 平台差异通过 npm `os`/`cpu` optionalDependencies 声明并由 entry 包在运行时 `require.resolve` 解析，而非环境变量或条件导入。
- 所有与二进制交互的 CLI 标志、退出码、probe 输出格式集中在 `src/index.ts` 内定义，消费者不得自行拼接 launcher 参数或解析其 stdout。
- 可测试性通过函数参数注入替代环境变量：`launcherPath` 接受 `resolvePackageJson` 钩子，`probe` 接受 `launcher` 路径，便于单元测试替换真实二进制。
- 构建目标由 `packages/*/prebuilds.json` 矩阵驱动，`scripts/build.ts` 中的 `TOOLS` 表是新增 C 源的唯一接入点，禁止绕过该表直接编译。
- 每个平台包的 `prepack` 钩子执行对应验证脚本（`verify-launcher-binary.mjs`、`verify-entry-lib.mjs`），确保发布前二进制完整性。
