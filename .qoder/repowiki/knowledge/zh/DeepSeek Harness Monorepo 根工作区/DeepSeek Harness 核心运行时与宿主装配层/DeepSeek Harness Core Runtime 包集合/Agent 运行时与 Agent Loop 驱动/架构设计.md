模块由两个相互依赖的子包组成，形成「接口 + 实现」分层：
- `@deepseek-ai/dsh-agent`（packages/core/agent）：纯接口与进程内服务层。`runtime-types.ts` 声明 `Agent`、`AgentOptions`、`AgentStatus` 及扩展点事件（`agent/pre-step`、`agent/request`、`agent/request-error`、`agent/turn-stopping`、`agent/error` 等），并通过 `declare module` 扩展 `@deepseek-ai/cordis` Events；`index.ts` 中的 `AgentRegistry` 作为 Cordis Service 维护 live agent 表、通过 `AsyncLocalStorage` 维护 process-local initiator 作用域（`withInitiator`/`withoutInitiator`/`currentInitiator`），并以 `enter`+`announce` 两阶段发布保证创建/注销有序；`inbox.ts` 提供基于 session 事件的增量投影，把 `next-turn`/`next-step` 待处理消息持久化到 session log；`dispatch.ts`、`consumed-work.ts`、`model-selection.ts`、`types.ts`、`invariant.ts` 分别承载事件分发、已消费工作追踪、模型选择策略、类型与不变量。
- `@deepseek-ai/dsh-agent-loop`（packages/core/agent-loop）：具体实现插件。`index.ts` 中的 `AgentLoop` 实现 `AgentFactory`，在构造时注入 `agents/sessions/llm/tools/systemPrompt`，安装 settings 段 `AGENT_LOOP_SETTINGS_NAMESPACE`，并通过 `ctx.agents.setFactory(this)` 把自身挂到 registry；`prepare()` 构建 `PreparedAgent`，用 `AbortController` 融合 caller 取消、owner fiber 卸载与工厂 teardown，再调用 `publish()` 进入 session/agent 注册表并发出 `agent/session-start`；`agent.ts` 中的 `ReactLoopAgent` 是状态机（idle/maintenance/running），通过 `Inbox` 消费输入、按 turn/step 边界驱动 LLM 请求，并在每个 step 调用 `tool-calls.ts` 执行工具；`tool-calls.ts` 以模型顺序提交工具调用，支持 exclusive barrier 与 bounded parallel pool（受 `maxParallelToolCalls` 限制），失败时记录 synthetic result 保持 replay 一致；`runtime-context.ts` 暴露 `RuntimeContextProjection` 供 agent 上下文使用。
依赖方向单向：agent-loop → agent → dsh-session/dsh-llm/dsh-tools/dsh-scope/cordis；agent 包不反向依赖 agent-loop，从而允许其他 loop 实现替换。
