模块以 `src/index.ts` 中的 `ToolRuntime`（继承自 `@deepseek-ai/cordis` 的 `Service`）为入口，集中管理工具的注册、可见性过滤、模式切换（native/code/both）和调度。

内部按职责拆分为多个文件：
- `schema.ts`：作者面向的统一 JSON 值 Schema DSL（`ValueSchemaSpec` 联合类型），编译为原始 JSON Schema，并提供 `defineTool`、`validateArgs`、`InferValue`/`InferArgs` 等类型推断辅助。
- `json-schema.ts`：受约束的原始 JSON Schema 子集校验器（`assertSupportedJsonSchema`、`validateJsonSchemaValue`），被 schema DSL、输出验证、Code Mode 类型生成共享。
- `code-mode.ts`：实现保留工具 `run_code`，将模型代码程序内的工具调用桥接回原生调度管线，维护每运行池的并发上限与子调用日志事件。
- `presentation.ts`：声明 UI 无关的 `ToolCallView` / `ToolResultView` 卡片词汇表，供工具通过 `presentCall`/`presentResult` 自定义渲染。
- `ts-types.ts` / `py-types.ts`：根据当前可见工具集合生成 TypeScript SDK 与 Python SDK 文本，注入到系统提示的 `tools:sdk` section。
- `types.ts` / `invariant.ts` / `testing.ts`：内部类型、不变量断言与测试夹具。

依赖方向单向向外：本模块通过 peerDependencies 引入 `@deepseek-ai/dsh-scope`（作用域层）、`@deepseek-ai/dsh-llm`（错误基类、ContentBlock）、`@deepseek-ai/dsh-session`（lossless JSON 快照）、`@deepseek-ai/dsh-code-runtime`（语言运行时）、`@deepseek-ai/dsh-system-prompt`（系统提示装配）、`@deepseek-ai/dsh-user-approval`（可选审批服务）以及 `@deepseek-ai/cordis`（Context/Service/Events）。`ToolLayer` 基于 `ScopedLayers` 实现全局与 agent 级工具/限制/守卫的叠加与遮蔽；`ToolRuntime` 暴露 `register`、`restrict`、`guard`、`execute`、`schemas`、`presentAs` 等 API，并通过 Cordis 事件 `tools/pre-execute`、`tools/execute`、`tools/post-execute`、`tools/code-dispatch-log`、`tools/result`、`tools/change` 暴露扩展点。Code Mode 下通过 `SDK_RENDERERS` 表按 `ctx.codeRuntime.language` 选择 TS/Python 渲染器，并以 `satisfies` 约束该表键集与 `CodeSdkLanguage` 联合一致，新增语言需三处同步修改。
