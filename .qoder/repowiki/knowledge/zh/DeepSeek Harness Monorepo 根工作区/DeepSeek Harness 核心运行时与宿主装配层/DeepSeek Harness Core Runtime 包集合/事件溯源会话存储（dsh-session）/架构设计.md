模块以 `Session`（纯类）+ `SessionStore`（继承自 `@deepseek-ai/cordis` 的 Service）为核心：`Session` 内部持有不可变的 `SessionEvent[]` 日志、`SurfaceManager`（有序表面投影）、以及请求头/上下文/派生消息的增量折叠缓存；`SessionStore` 通过 `ctx.sessions` 注册为 Cordis 服务，管理会话生命周期（`prepare` → `enter` → `announce`），并扩展 `Context.Events` 声明 `session/created`、`session/disposed`、`session/event`、`session/flush` 四个事件，供持久化插件订阅。

内部按职责拆分为多个文件：`types.ts` 定义 `SessionId`、`SessionHeader`、`SessionEventMap`（merge-extensible）、`TurnEndReasonMap` 等核心类型；`surface.ts` 维护消息可投影事件的有序序列及 `replace` 操作校验，是 `deriveMessages()` 的唯一来源；`request-header.ts` 折叠 `request/header` 事件重建请求元数据；`json.ts` 提供一次性 lossless JSON 快照工具；`chunk-rows.ts` 实现事件到紧凑行的编解码；`repair.ts` 处理中断 turn 的恢复；`preparation.ts` 封装创建选项；`known-event-types.ts` 导出已知事件类型集合。

依赖方向单向向外：仅依赖 `@deepseek-ai/cordis`、`@deepseek-ai/dsh-scope`、`@deepseek-ai/dsh-llm`、`@deepseek-ai/dsh-brand`、`@deepseek-ai/dsh-typert-protocol`，不反向引用任何上层业务包；通过 `exports` 字段将根入口、`invariant`、`types`、`surface` 分别暴露为独立子路径，使浏览器端可只引入 surface 子集。构建使用 `tsdown.config.ts` 生成 Node ESM 产物，`package.json` 中 `main`/`types`/`files` 限定发布范围。
