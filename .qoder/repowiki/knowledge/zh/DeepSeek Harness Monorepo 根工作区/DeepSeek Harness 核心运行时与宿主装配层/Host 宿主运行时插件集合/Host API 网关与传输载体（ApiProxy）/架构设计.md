模块按四层组织：
- 契约层 `src/api/`：纯浏览器可导入的 TypeScript 类型与 Zod schema，每个领域（sessions、workspace、settings、credentials、llm、goals、agent-presets、subagents、events、downloads、host）以 `<domain>.ts` + `<domain>.schema.ts` 成对声明；`api/index.ts` 汇总为 `ApiProxy` 根接口，`rpc-map.ts` 通过 `RpcMethodMap` 把方法名与 payload/value 类型绑定。
- 实现层 `src/api-proxy.ts`：`createApiProxy(ctx, defaults)` 基于 Cordis Context 注入的 `sessions/subagents/workspace/llm/settings/...` 服务拼装具体行为，维护 pending approval/question 表、冷会话空白探测、投影折叠、SSE frame 队列等核心逻辑。
- 传输层 `src/fetch/`：`handler.ts` 暴露 `toFetchHandler(api)` 将 `ApiProxy` 映射到 WHATWG Request/Response，维护 `UNARY_ROUTES` 路由表并处理 `/api/events.mux`、`/api/events.host`、`/api/session.export` 等无信封 SSE 流；`client.ts` 提供 `AbstractApiClient` 与 `InProcessApiClient`，封装 rpcId 生成、四象限信封编解码、SSE 帧解析与批量 envelope 观察。
- 插件入口 `src/index.ts`：导出 `ApiProxyService extends Service`，通过 `static inject` 声明依赖的服务键，并把 `ctx.apiProxy` 挂到 Cordis Context 上；同时暴露 `Config`（nativeOpen、sessionExportCompressionLevel、coldBlankProbeMaxBytes）。
依赖方向单向向外：契约层零 Node 依赖，实现层仅消费 `@deepseek-ai/dsh-*` 领域包，传输层不感知业务语义，新增领域只需在 `api/` 加一对文件并在 `rpc-map`、`UNARY_ROUTES`、`UNARY_VALUE_SCHEMAS` 三处同步注册。
