- 每个领域方法以 `<domain>.ts` 声明窄接口、`<domain>.schema.ts` 声明 Zod schema，并通过 `rpc-map.ts` 中的 `RpcMethodMap` 把方法名与 payload/value 类型静态绑定。
- 服务端路由通过 `UNARY_ROUTES` 表集中注册，每条记录包含同方法的 schema 与 invoke 闭包，新增方法必须同时在客户端的 `UNARY_VALUE_SCHEMAS` 中镜像注册以保证编译期一致性。
- 所有跨进程错误统一收敛为 `{ code, message, details }` 形式的 `RpcError`，由 `err()` 包装并回显请求的 `rpcId`，业务异常从不抛出而是返回 `ok: false`。
- 可选能力（如 settings、credentials、sessionProjections、approval）通过 `ctx.get(...)` 惰性读取，缺失时降级为 absent 而非报错，使部署可以按需裁剪。
- SSE 流采用 `data: <JSON>` + 双换行分隔的手工分帧，服务端用 `ReadableStream` 写入、客户端用 TextDecoder 缓冲并按 `\n\n` 切分，单帧解析失败仅丢弃该帧而不中断流。
- 配置项通过 `z.object({...}).default(...)` 声明默认值，并在 `ApiProxyService` 构造函数中以条件展开的方式选择性注入到 `createApiProxy`，未提供的选项直接省略键。
