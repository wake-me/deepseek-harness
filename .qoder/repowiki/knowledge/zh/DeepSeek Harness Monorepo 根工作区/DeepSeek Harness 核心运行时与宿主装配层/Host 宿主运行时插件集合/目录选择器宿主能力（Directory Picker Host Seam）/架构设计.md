模块由四个子包按职责分层组成：
- `directory-picker`：定义核心契约——`DirectoryPicker` 抽象 Service、`DirectoryPickerCapabilities` 合并扩展的 discriminated union（`native`/`browse`）、`DirectoryEntry`/`DirectoryListing` 数据模型以及 `DirectoryPickerError` 错误码；通过 Cordis 的 Context 扩展注入 `ctx.directoryPicker`。
- `directory-picker-browse`：基于 Node `fs/promises` 实现 `browse` 能力，使用流式 `opendir` + 名称排序有界窗口（`boundedInsert`，内存 O(keep)）完成单级目录列举，并支持创建子目录；所有 FS 操作通过 `raceAbort` 与 `AbortSignal` 绑定以支持取消。
- `directory-picker-native`：实现 `native` 能力，macOS 调用 `osascript`，Linux 依次尝试 `zenity`/`kdialog`，Windows 通过 `win32-dialog.ts` 用 koffi 驱动 IFileOpenDialog COM 并在独立子进程中运行以避免主线程阻塞；平台分支集中在 `native-picker.ts`，可注入 `run`/`pickWin32Dialog` 以便测试。
- `directory-picker-auto`：Cordis 插件，启动时读取 `webServer.host`、`process.platform`、`SSH_*`/`DISPLAY`/`WAYLAND_DISPLAY` 等主机事实，通过纯函数 `resolveDirectoryPickerBackend` 决定挂载 `native` 还是 `browse`，并以 `loader.create` 动态加载对应后端包与客户端 UI 表面，卸载时按逆序 remove 并等待 fiber 清理。
依赖方向单向：auto → (native|browse) → directory-picker（仅类型），各后端不互相引用，新增后端只需实现 `DirectoryPicker` 并注册新 `kind`。
