- 每个后端都继承 `DirectoryPicker` 并在构造时缓存一个稳定的 capability 对象，`capability()` 直接返回该实例以满足“能力对象生命周期稳定”的契约。
- 对外暴露的错误统一通过 `DirectoryPickerError` 携带闭合的 `code`（`directory-unreadable`/`directory-exists`/`directory-create-failed`），禁止直接使用字符串匹配业务语义。
- 所有可能长时间阻塞的异步操作（FS 读取、stat、外部命令）都通过 `AbortSignal` 进行竞态取消，并在 abort 后吞掉被遗弃操作的关闭失败以避免未处理拒绝。
- 路径参数在进入 FS 前强制校验 `fullyQualified`，拒绝相对路径或裸 UNC，防止 wire 值被静默重定向到 host cwd。
- 平台特定逻辑集中放在独立文件（如 `native-picker.ts`、`win32-dialog.ts`），并通过可选的 `internals` 注入点（`platform`、`run`、`pickWin32Dialog`）使行为可在单元测试中替换。
- 自动选择器将后端决策封装为纯函数 `resolveDirectoryPickerBackend(facts)`，仅依赖不可变的主机事实快照，确保一次解析结果在整个服务生命周期内稳定。
