- CLI 入口通过 Commander 的 `allowUnknownOption()` + `passThroughOptions()` + `enablePositionalOptions()` 将未知参数透传给被启动的应用，自身只消费 `--profile`/`--patch`/`--dump-config` 等 launcher 级选项。
- 每种模式（profile/plugin/dump-config）封装为独立的 `runXxx` 函数并在 `bin.ts` 中以 `switch (invocation.mode)` 动态 `await import(...)` 加载，避免无关代码进入冷启动路径。
- Patch 层组合遵循固定顺序：bundle 层 → 配置文件层 → `$DSH_HOME/cordis.patch.yml` → `--patch` 覆盖层 → 遥测开关，新增层必须插入该序列的正确位置。
- 对用户 patch 文件（profile 的 `cordis.patch.yml` 与 `$DSH_HOME/cordis.patch.yml`）统一通过 `watchUserPatches` 监听变更并以 `structuredClone` 重新 compose，防止引用共享导致状态泄漏。
- 错误与帮助输出通过 Commander 的 `program.error(...)` / `program.help()` 处理，并由 `exitOverride()` + try/catch 捕获 `CommanderError` 统一设置退出码。
- 相对路径 spec（如 `.`、`../pkg`）在转发给 pnpm 前通过 `anchorPathSpec` 锚定到调用者 cwd，避免在 profile 目录下误解析。
