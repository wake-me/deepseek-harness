模块以 `src/bin.ts` 为 Node 可执行入口（package.json `bin.dsh` → `lib/bin.js`），通过 Commander 在 `src/args.ts` 中解析三类 invocation：`profile`、`plugin`、`dump-config`，再由 `bin.ts` 的 switch 动态 `import()` 对应处理器，实现按模式懒加载、减少冷启动体积。
- `profile-boot.ts` 是核心编排器：调用 `@deepseek-ai/dsh-app-boot` 的 `loadProfile`/`composeEntries`/`boot`，按固定顺序叠加 patch 层（bundle 层 → 配置文件层 → `$DSH_HOME/cordis.patch.yml` → `--patch` 覆盖层 → 遥测开关），并通过 `watchUserPatches` 对两个用户 patch 文件启用热重载；同时注入 `DSH_LAUNCH_ENVIRONMENT_KEY`、`provideCmdline`、进程信号与 fail-loud 关闭钩子。
- `plugin.ts` 作为 pnpm 转发器：首次使用初始化 profile（模板来自 `PROFILE_TEMPLATES`），在 profile 目录内 `spawnSync('pnpm', ...)`，成功后根据已安装包是否声明 `dsh.bundle` 自动同步 `dsh.profile.bundles` 列表。
- `dump-config.ts` 走无启动路径，仅用 include 插件的 patch 算法渲染分层 YAML，用于诊断。
- `process-shutdown.ts` 提供统一的有界退出控制器；`profile-shutdown.ts` 与 `src/profile-boot.ts` 协作保证 fiber 正确 dispose。
- `config/agent-presets/` 内置 agent preset 根目录，由 `runProfile` 在 composition 阶段以 `roots: [{ path, trust: 'system' }]` 注入，使预设可在任意 profile 下被引用。
- 构建产物由 `tsdown.config.ts` 指定入口 `lib/types/bin.js`，输出 ESM 至 `lib/`，配合顶层 `tsc -b` 生成 d.ts；发布文件包含 `lib/*.js` 与 `config/`。
