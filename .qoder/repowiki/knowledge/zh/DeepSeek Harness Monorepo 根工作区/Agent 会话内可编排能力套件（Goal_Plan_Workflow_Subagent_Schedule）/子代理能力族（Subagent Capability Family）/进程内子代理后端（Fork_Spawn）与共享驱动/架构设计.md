模块由三个独立 npm 包组成，依赖方向单向：`subagent-fork-in-process` 与 `subagent-spawn-in-process` 作为面向上层的 `SubagentProvider` 实现，仅负责注册到 `ctx.subagents` 并构造请求参数；两者共同依赖 `subagent-in-process-driver` 提供的 `startInProcessRun` 来创建子 Agent、驱动单 turn 生命周期、映射停止原因并产出 `SubagentResult`。

- `subagent-in-process-driver/src/index.ts`：核心驱动，完成深度限制校验、`captureDelegatedPolicyOverrides`/`applyChildComposition` 策略继承、通过 `parent.ctx.agents.create` 创建子 AgentHandle、监听 signal 取消、调用 `child.followup` 发送 prompt 并在 `whenIdle` 后通过 `foldConsumedWork` + `finalAssistantOutput` 从会话事件切片中抽取结果。
- `subagent-in-process-driver/src/structured.ts`：为每个子 Agent 在 setup 阶段动态注册名为 `structured_output` 的工具与第 190 序的 systemPrompt section，使用 WeakMap 按 ToolExecution 暂存值，并通过 `tools/result` 事件做两阶段提交（嵌套 Code Mode 场景下先挂起 pending，外层执行完成后才写入 captured），同时用 `tools.guard` 保证结构化输出只被接受一次。
- `subagent-fork-in-process`：实现 `inheritsParentContext = true`，通过 `completedTurnPrefix` 截取父会话最后一个 `turn/end` 之前的完整事件序列作为 seed，使子代理继承已完成的对话上下文。
- `subagent-spawn-in-process`：实现 `inheritsParentContext = false`，不传 seed，子代理从零会话开始。

两个 Provider 均声明 `capabilities: { outputSchema, depthLimit, toolFilter, persona }`，并通过 `inject = ['subagents']` 以 Cordis 插件形式暴露 `apply(ctx, config)`。
