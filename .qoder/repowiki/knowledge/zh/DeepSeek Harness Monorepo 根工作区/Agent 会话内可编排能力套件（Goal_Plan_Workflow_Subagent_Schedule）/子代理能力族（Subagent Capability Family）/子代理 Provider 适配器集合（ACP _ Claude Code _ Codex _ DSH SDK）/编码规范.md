- 每个 provider 以命名导出 `name`、`inject`、`Config`（schemastery zod schema）、`apply(ctx, config)` 以及一个实现 `SubagentProvider` 的类构成插件契约，禁止使用默认导出以免丢失 loader metadata。
- Provider 类的 `capabilities` 固定为 `NO_START_CAPABILITIES`，且 `inheritsParentContext = false`，显式声明出进程子代理不具备 start-time 能力且不继承父会话上下文。
- 子进程通过注入的 `ctx.subprocess.spawn` 而非本地 `child_process` 启动，使子树受共享 subprocess seam 的环境清洗、超时与树级回收管理。
- dispose 采用两级优雅退出：先写 stdin EOF 给子进程 flush 窗口（`disposeEofGraceMs`，默认 6000ms），再调用 `terminate()` 触发 SIGTERM→SIGKILL 阶梯（`disposeGraceMs`，默认 3000ms）。
- `disposeGraceMs`/`shutdownTimeoutMs`/`disposeEofGraceMs` 等时间参数在 `apply` 中通过 `assertPositiveFinite` 与 `MAX_TIMER_DELAY_MS` 上限双重校验，防止 Node timer 溢出。
- 工作目录解析统一遵循“配置绝对路径优先 → 父 session cwd 回退 → 缺失报错”的策略，并使用 `validateConfiguredCwd`/`resolveChildCwd` 在加载或启动早期失败，避免隐式回落到 harness 启动目录。
