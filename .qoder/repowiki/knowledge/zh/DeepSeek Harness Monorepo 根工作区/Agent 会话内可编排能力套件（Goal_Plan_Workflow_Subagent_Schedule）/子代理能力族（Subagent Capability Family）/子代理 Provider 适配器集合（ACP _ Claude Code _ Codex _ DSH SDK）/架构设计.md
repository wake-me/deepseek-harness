本模块由四个并列的 npm 包组成，每个包对应一种外部子代理后端，遵循相同的分层结构：
- `src/index.ts`：插件入口，定义 `Config`（基于 `@deepseek-ai/schemastery` 的 zod schema）、导出 `name`/`inject`/`apply`，并在 `apply(ctx, config)` 中构造一个实现 `SubagentProvider` 的类，调用 `ctx.subagents.registerProvider` 注册到 Cordis。
- `src/run.ts`：运行期驱动，负责 spawn 子进程、建立协议通道、处理取消与优雅退出（EOF grace → SIGTERM → SIGKILL 阶梯式终止），返回 `SubagentRun`。
- 产品特定适配层：`subagent-acp` 直接对接 `@agentclientprotocol/sdk`；`subagent-codex` 额外包含 `wire.ts` 作为对 Codex app-server 0.147.0 JSON-RPC 协议的窄接口封装；`subagent-claude-code` 通过 `process.ts` 把共享 `SubprocessHandle` 投影为 Anthropic Agent SDK 的 `SpawnedProcess` 接口，并处理 Windows batch shim 与环境覆盖。
- 依赖方向单向向上：各 provider 仅依赖共享抽象 `@deepseek-ai/dsh-subagent`、`@deepseek-ai/dsh-subprocess`、`@deepseek-ai/cordis`，不反向引用其他 provider；能力声明统一为 `NO_START_CAPABILITIES`（即 `outputSchema`/`depthLimit`/`toolFilter`/`persona` 均为 false），因为出进程子代理无法在 start 前满足这些约束。
- 工作目录解析策略一致：优先使用配置的绝对 `cwd`（加载时校验可进入性），否则回退到父 session 的 `header.cwd`，缺失则抛出明确错误，避免隐式落入 harness 启动目录。
- 测试位于各包 `tests/` 下，包含 e2e 与 spec，并通过 `loader-composition.e2e.ts` 验证 Cordis 插件加载组合。
