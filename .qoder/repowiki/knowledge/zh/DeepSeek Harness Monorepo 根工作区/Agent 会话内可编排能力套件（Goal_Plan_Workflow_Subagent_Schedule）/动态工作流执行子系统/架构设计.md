模块以四个独立 npm 包按职责分层组织：
- `workflow/` 定义核心 seam：`WorkflowEngine` 抽象类、`WorkflowRun`/`WorkflowStartRequest`/`WorkflowResult` 等运行时类型、`WorkflowError`（含 `fatal` 标志区分致命错误与 per-item null）以及 `workflow/*` 事件契约（start/phase/log/agent-start/agent-end/end），并通过 Cordis `Context` 扩展注入 `ctx.workflowEngine`。
- `workflow-worker-thread/` 是具体实现：`host.ts` 在宿主进程创建 Node Worker 并通过 `MessageChannel` 运行；`session.ts` 维护 worker 侧会话、`ChildRpcBridge` 管理子 agent RPC 生命周期；`runtime.ts` 用 `node:vm` 编译并执行模型脚本，暴露 `agent()`/`pipeline()`/`parallel()`/`phase()`/`log()` 钩子，严格限制选项白名单并将返回值经 `realm.ts` 序列化为纯 JSON；`protocol.ts` 用双向 enum + payload map 定义 host↔worker 消息协议，所有分支使用 `assertNever` 保证闭集。
- `tool-workflow/` 注册模型可见的 `workflow` 工具，负责参数 schema、结果渲染、将 `workflow/*` 事件录制到 Session，并把父 step 的 abort signal 桥接到 `run.cancel`。
- `tool-ralph/` 注册固定策略 `ralph` 工具，内嵌一段不可篡改的 Ralph 循环脚本，强制要求 fresh structured-output provider，并对跨边界返回的报告做防御性解码与字符上限截断。
依赖方向单向：tools → worker-thread engine → core workflow seam；worker-thread 仅依赖 core 的类型与错误，不反向引用 tools。
