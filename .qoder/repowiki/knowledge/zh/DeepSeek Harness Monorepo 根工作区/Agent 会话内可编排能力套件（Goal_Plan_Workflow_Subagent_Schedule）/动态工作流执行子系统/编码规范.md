- 对外能力通过继承 `WorkflowEngine` 或调用 `ctx.workflowEngine.start(...)` 暴露，并以 `workflow/*` 事件发布生命周期而非直接回调。
- 所有配置接口均配合一个同名的 `z<Config>` schemastery schema 导出，默认值由 schema 填充后再断言为 `ResolvedConfig`。
- 错误分类采用 `WorkflowError` + 字符串字面量 `code`（如 `SCRIPT_PARSE`/`META_INVALID`/`CANCELLED`）+ `fatal` 标志，致命错误由组合器重新抛出，普通失败映射为 per-item `null`。
- Worker 与宿主之间的通信集中在 `protocol.ts`，以双向 enum 加 payload map 描述，接收端用 `assertNever` 穷尽分支，发送端使用泛型 tag/payload 使类型不匹配成为编译期错误。
- 模型脚本通过 `node:vm` 在独立 context 中执行，仅暴露受控全局（agent/pipeline/parallel/phase/log/args），且所有跨边界返回值经 `realm.ts` 材质化为纯 JSON，禁止传递函数或 realm 对象。
- 工具插件通过 `defineTool` 注册，并在 `apply(ctx, config)` 中使用 `ctx.systemPrompt.section` 注入显式使用策略（explicit-ask guidance），而非写入部署 persona。
