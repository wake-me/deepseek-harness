- 所有持久化数据在边界处通过严格正则与 `hasExactKeys` 校验后冻结（`Object.freeze`），并以 `ScheduleLogError` 报告格式错误。
- 输入校验统一抛出带稳定 `code` 字段的 `ScheduleInputError`（如 `invalid_prompt`、`not_future`、`frequency_too_high`），工具层再映射为闭 union 的错误值返回。
- 对会话事件的读写均包裹在 `runScheduleTransaction` 中串行执行，避免同一 agent 上并发修改 schedule 状态。
- 每次持久化写操作前后都调用 `flushSchedulePersistence` 作为 barrier，确保事件被下游持久化监听器确认后才继续。
- 运行态通过 `requestDrive` + `clearTimer` + `arm` 的节流模式合并多次触发，并使用 `waitForIdle` 在 `runMaintenance` 冲突时退避到 idle 边界重试。
- 面向模型输出的提醒文案通过 `renderReminderFraming` / `renderEveryReminderBatchFraming` 生成，将动态字段以 JSON 字符串嵌入固定模板，防止提示注入。
