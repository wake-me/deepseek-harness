模块以 Cordis 插件形式暴露 `apply(ctx)` 入口（`src/index.ts`），监听 `agent/created` 事件为每个 root agent 创建独立的 `ScheduleRuntime` 实例，并注册 `schedule_create/list/delete` 三个工具。

内部按职责分层：
- `domain.ts`：纯函数层，负责 v1 协议解码（`decodeScheduleChange`）、事件折叠（`foldScheduleEvents`）、记录构造（`createAfterScheduleRecord`/`createAtScheduleRecord`/`createEveryScheduleRecord`）、时间解析（IANA 时区、UTC/偏移量、本地日历）以及注入安全的提醒文案渲染（`renderReminderFraming`/`renderEveryReminderBatchFraming`）。
- `runtime.ts`：进程内可销毁的运行态，维护定时器、空闲等待与故障状态，通过 `dueDecision` 在每次驱动时选择下一个 due 的一次性或固定频率批次，调用 `agent.runMaintenance` 投递 followup 消息并追加 `schedule/change` 事件。
- `persistence.ts`：封装共享 session 持久化屏障 `ctx.sessions.flush`，保证事件落盘后再继续后续逻辑。
- `transaction.ts`：串行化同一 agent 上的 schedule 事务，避免并发重入。
- `tools.ts`：基于 `@deepseek-ai/dsh-tools` 的 `defineTool` 注册三个工具，使用 JSON Schema 严格约束参数与输出，并通过 `runCancellableScheduleTransaction` 包装执行体。
- `types.ts`、`invariant.ts`：共享类型与运行时不变量检查。

依赖方向单向：tools → runtime → domain/persistence/transaction；runtime 仅读 `agent.session.events` 进行回放式投影，不直接持有外部状态。所有变更通过 `schedule/change` 事件写入会话日志，由 `foldScheduleEvents` 从 seedLength 之后重新计算活跃集合，实现跨重启/子代理的确定性恢复。
