本模块是仓库根 `scripts/` 下的纯脚本集合，按职责大致分为四层：
- 调度层：`run-gates.ts` 定义 `Gate`/`Mode` 模型，通过 `gatesForMode` 为 `ci-primary|ci-static|ci-coverage|ci-snapshot|ci-consumers|check-all|doc-sync` 等模式组装有向无环依赖图，使用内置并发池（`runGates`）以 `pnpm run/exec` 形式无 shell 地启动子进程，并通过 `DSH_GATE_CONCURRENCY`、`DSH_COVERAGE_MAX_WORKERS` 等环境变量调节并行度。
- 共享基础设施：`ts-project.ts` 提供 `TypeScriptProject`，基于 `tsconfig.host.json` 解析并扁平化所有 project references 构造单一 `ts.Program`，供需要跨文件语义分析的脚本复用；`repo-files.ts`、`slot-walk.ts`、`cordis-walk.ts` 提供统一的仓库文件遍历能力。
- 验证器/生成器：每个 `.ts` 对应一个可独立运行的 gate（如 `package-invariants.ts`、`verify-cordis-config.ts`、`gen-third-party-notices.ts`、`translation-pairing.ts`、`merge-translation-pairing.ts`），多数遵循“读取仓库 → 产出 violations 列表或生成产物”的单向数据流，并通过同名 `*.spec.ts` 进行回归测试。
- 平台适配层：`.sh` 脚本（`check-vendor-manifest.sh`、`prepare-ci-bubblewrap.sh`、`wine-windows-gates.sh`、`merge-translation-pairing-driver.sh`）仅封装平台差异，由上层 TS 脚本调用。
依赖方向严格自上而下：gate 编排 → 具体验证器 → 共享基础设施，禁止反向引用；所有脚本通过 `pnpm` 暴露的 package script 名称被外部 CI 调用，而非直接执行。
