本模块由四个相互协作的子包组成，按依赖方向自下而上分层：
- `session-query/`：定义抽象服务 `SessionQueryEngine`（继承自 Cordis `Service`），声明统一的会话读取、事件过滤、标题折叠、表面快照、血缘追踪等 API，并通过 `declare module '@deepseek-ai/cordis'` 将 `ctx.sessionQuery` 注入到全局 Context；内部通过 `corpus.ts` 聚合 live/persisted 源、`documents.ts` 构建搜索文档、`filters.ts` 编译逻辑谓词、`tracing.ts` 计算血缘。
- `session-query-sqlite/`：基于 SQLite FTS5 实现 `SqliteSessionQueryEngine`，维护持久化表 `persisted_sessions`/`persisted_docs` 与临时内存表 `temp.live_sessions`/`temp.live_docs`，在每次搜索前通过 `_reconcile` 对比 persistence 快照与 live sessions 的差异并原子写入；使用 `schema.ts` 管理数据库版本与 journal mode，`query.ts` 负责请求归一化、SQL WHERE 片段生成与游标编解码。
- `tool-session-query/`：作为 Cordis Loader 插件，通过 `defineTool` 注册 `session_search`、`session_event_search`、`session_trace`、`session_event_trace`、`session_event_read` 五个面向模型的 tool，并在 `systemPrompt` 中注入使用说明，调用层通过 `workspace-access.ts` 做工作区授权边界检查。
- `session-log-export/`：Web 端专用插件，注册 `/export` 命令并将下载状态交由浏览器侧 Host ZIP 端点处理，仅包含极薄的 `apply(ctx)` 入口。
依赖方向严格单向：`tool-session-query` → `session-query`；`session-query-sqlite` → `session-query`；`session-log-export` 独立不依赖其他子包。
