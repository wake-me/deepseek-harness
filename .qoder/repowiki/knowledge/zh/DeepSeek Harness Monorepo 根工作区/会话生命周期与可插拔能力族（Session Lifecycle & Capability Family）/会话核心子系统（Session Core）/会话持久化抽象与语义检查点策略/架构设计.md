模块由两个独立 npm 包组成，职责清晰分层：
- `session-persistence`（`@deepseek-ai/dsh-session-persistence`）：以 `SessionPersistence` 抽象类为对外服务契约（定义 `create/append/load/inspect/readFrom/list/listSnapshots/locate/readRaw`），通过 `PersistenceCoordinator` 实现跨后端统一的写路径编排——按 session id 串行化操作链（`chains` Map）、写后批量合并（`SessionWriteBehind` 固定窗口 + 屏障）、冷启动准备的共享 LRU 缓存与独占预留（`SessionPreparations`，状态机 `loading→ready→committing→reserved`）、版本迁移与旧格式拒绝（`assertSupportedEvents`、`migrateLegacy*Event`）、崩溃修复（`interruptedTurnClosers` + `commitRepair`）。具体存储后端只需实现 `PersistenceBackend` 接口（`loadStored/loadStoredFrom/appendBatch/commitRepair/list`），协调器负责序列化、修订号比较、事务性提交与废弃回收。
- `session-checkpoint-policy`（`@deepseek-ai/dsh-session-checkpoint-policy`）：作为 Cordis 插件（`name = 'session-checkpoint-policy'`，`inject = ['llm','sessionPersistence','sessions','tools']`），在 `llm/stream`、`tools/execute`、`agent/pre-step` 三个钩子处调用 `ctx.sessions.flush` 完成语义检查点，确保模型请求、工具副作用和步骤边界前日志已落盘；失败时 fail-closed，不触发下游适配器或工具体。
依赖方向单向：checkpoint-policy → persistence（仅消费 `ctx.sessionPersistence`），persistence 不反向依赖 checkpoint-policy；两者均依赖 `@deepseek-ai/dsh-session`、`@deepseek-ai/cordis` 等核心包并通过 `peerDependencies` 声明。
