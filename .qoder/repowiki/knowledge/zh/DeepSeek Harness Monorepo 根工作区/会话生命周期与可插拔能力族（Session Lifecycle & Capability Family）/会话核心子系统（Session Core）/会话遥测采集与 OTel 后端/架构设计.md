模块由两个协作的包组成，通过 `SessionTelemetryBackend` / `SessionTelemetrySink` 接口解耦采集与上报：
- `session-telemetry`（seam）：`src/index.ts` 定义 `SessionTelemetryRecord`、`SessionTelemetrySeverity`、`SessionTelemetrySink`、`SessionTelemetryBackend` 抽象以及 `session-telemetry/record` 水线事件；`src/coordinator.ts` 中的 `SessionTelemetryCoordinator` 订阅 cordis 的 `session/created`、`session/event`、`session/flush`、`agent/error`、`session/disposed` 等总线事件，执行固定 chunk 投影（仅首块）、身份属性拼装、严重级别映射、`structuredClone` 深拷贝并通过 `ctx.waterfall('session-telemetry/record', ...)` 运行部署挂载的脱敏规则，最终调用后端 `emit`；维护模块级 `WeakMap<Session, number>` 手递游标以支持 HMR 重接入与 on-demand 回放。
- `session-telemetry-otel`：`OpenTelemetrySessionBackend` 继承自 seam 的 `SessionTelemetryBackend`，依据 `Config.mode`（FULL / FEEDBACK_ONLY / DISABLED）选择 live 或 on-demand 模式构造 coordinator，使用 `LoggerProvider` + `BatchLogRecordProcessor` + `OTLPLogExporter` 将记录映射为 OTel log 条目，按 channel 分属不同 logger scope（`@deepseek-ai/dsh-session-telemetry-otel` 与 `/ops`），并在 shutdown 时以超时保护 provider 关闭。
依赖方向单向：otel → seam → (`@deepseek-ai/cordis`、`@deepseek-ai/dsh-session`)，seam 不感知任何具体上报 SDK。
