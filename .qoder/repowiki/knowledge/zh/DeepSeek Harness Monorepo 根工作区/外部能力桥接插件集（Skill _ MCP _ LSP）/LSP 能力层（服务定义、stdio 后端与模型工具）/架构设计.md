模块由三个相互依赖的 Cordis 子包组成，形成自下而上的三层架构：
- `lsp/`（服务定义层）：导出 `LspService` 接口与 `Lsp` 实现，维护 `extension→Route` 映射表，通过 `registerProvider` 原子校验并注册 provider 的 branded id 与扩展名映射，`query` 仅按文件最终扩展名路由到对应 provider，对外暴露 `goToDefinition/findReferences/goToImplementation/hover` 四个语义操作，禁止 JSON-RPC 逃逸。
- `lsp-stdio/`（stdio 后端层）：作为插件 `apply(ctx, config)` 注入 `fs/lsp/subprocess`，为每个配置的本地语言服务器创建隔离的 `LocalLspProvider`，按规范化的 workspace key 池化单例 `LspInstance`，通过 `framing.ts` 进行 JSON-RPC 帧编解码、`translate.ts` 做位置编码协商与结果归一化；按 workspace 串行化队列保证 transient-open 生命周期顺序，并在传输失败时透明重试。
- `tool-lsp/`（模型工具层）：注册名为 `lsp` 的单一工具，把模型传入的“基于 1 的 UTF-16 光标坐标”转换为 seam 的零基位置，调用 `ctx.lsp.query`，对结果做截断与渲染，并通过 `systemPrompt.section` 注入引导文案。
依赖方向严格单向：`tool-lsp` → `lsp` ← `lsp-stdio`，后者只消费前者导出的类型与错误码，不反向依赖工具层。
