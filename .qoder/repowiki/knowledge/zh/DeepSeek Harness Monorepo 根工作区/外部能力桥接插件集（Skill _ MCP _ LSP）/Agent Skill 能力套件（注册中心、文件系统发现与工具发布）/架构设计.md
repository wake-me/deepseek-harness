本模块由四个相互协作的 npm 包组成，围绕 `@deepseek-ai/dsh-skill` 定义的 `SkillProvider` 接口形成清晰的依赖方向：
- `skill/`（核心库）：导出 `SkillRegistry`、`SkillProvider`、`SkillCandidate`、`SkillDefinition`、`SkillInvocationPolicy` 等类型与 `renderSkillContent`、`escapeText` 等渲染工具；通过 Cordis `Service` 挂载到 `ctx.skills`，实现按 scope chain 的分层注册（global → 各 preset layer），并以 rank + providerOrder + localOrder 三级排序去重；维护 collect 缓存与 `skills/change` 事件以支持增量刷新。
- `skill-badge/`：一个轻量 provider，将内置的 `dsh-badge.md` 作为 `bundled` source 的技能注册到 `ctx.skills`，使用 `BUNDLED_SKILL_RANK` 获得高优先级。
- `skill-filesystem/`：基于 chokidar 的本地文件系统 provider，扫描 `.dsh/skills`、`.agents/skills`、自定义目录、`$DSH_HOME/skills`、`$DSH_AGENTS_HOME/skills` 以及可选的 `DSH_BUNDLED_SKILL_DIR`，解析 YAML frontmatter 生成 candidate，并通过 `SkillWatchManager` 对根路径做稳定监听、失败回退与失效广播。
- `tool-skill/`：消费 `ctx.skills`，注册名为 `skill` 的模型工具（`defineTool`），并在 `agent/pre-step` 钩子中注入会话级 `<available_skills>` 目录消息和 `/name` 显式调用手势，将技能内容以 `<skill_content>` 块注入对话。
依赖方向单向：`skill-badge`、`skill-filesystem`、`tool-skill` 均只依赖 `@deepseek-ai/dsh-skill` 导出的类型与常量，核心库不反向依赖任何具体 provider。
